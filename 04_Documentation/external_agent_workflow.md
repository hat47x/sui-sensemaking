# 外部エージェント連携ワークフロー（Copilot 等・定額課金 AI）

想定読者: Microsoft Copilot、Copilot Studio、ChatGPT Enterpriseなどの定額課金型AIエージェントに分析の一部を依頼したい利用者と、エージェントを設定する運用担当者。

本書は、sui-sensemakingの「エージェントへ依頼」からタスクシートを書き出し、外部エージェントの応答を「応答を取り込む」に貼り付けるまでの手順を説明します。追加開発なしで、応答を未レビューの提案として取り込む運用を対象とします。

対象外: Copilot Studioのテナントの構築と管理。これらはMicrosoftの公式手順を参照してください。

本書を読むことで、タスクシートの書き出しから応答の取り込みまでを手作業で再現でき、外部エージェント側で確認すべきデータの取り扱いを判断できます。

## 基本方針

- sui-sensemakingは外部エージェントと直接通信しません。書き出しと取り込みは、人間がタスクシートやJSONをコピーして貼り付けるか、ファイルを添付する明示的な操作で行います。
- エージェントの出力は、常にAIが作成した未レビューの提案です。応答を読み込むだけでは文書は変わらず、個々の提案を採用するかどうかは人間が判断します。
- 応答に点数・順位・確度などの数値評価が含まれていても、取り込み時に破棄します。エージェントによる採点を利用する運用は想定していません。
- 書き出し時には既存の共有・書き出しに関する安全確認（SafeModeと共有前確認）を、取り込み時には入力データの検証と無害化を必ず実施します。

## 最短運用（追加構築なし）

Copilotなどのチャット欄にタスクシートを貼り付ける方法なら、追加の連携機構は必要ありません。

1. sui-sensemakingでカードや島を選択し、「詳細」表示を有効にしてから「エージェントへ依頼」を開きます。
2. 依頼の種類（島のタイトル候補・統合できそうな組の候補・文章の草稿・対立する視点・違和感の指摘・自由な分析）を選び、書き出す範囲を確認してタスクシート（.md）をダウンロードまたはコピーします。
3. Copilotのチャットにタスクシートを貼り付け（またはファイルを添付）ます。
4. 返ってきたJSON（コードフェンス付き）をコピーし、sui-sensemakingの「エージェント応答を取り込む」に貼り付けます。
5. 解析結果（受理件数・警告件数）を確認し、提案ごとに「取り込む」または「破棄する」を選びます。取り込んだ提案は未レビューの状態で反映され、Cmd/Ctrl+Zで個別に取り消せます。

## エージェント化する場合（推奨・再現性向上）

Copilot Studioなどでエージェントを一つ設定しておけば、毎回チャットで同じ指示を説明し直さずに済み、手順を再現しやすくなります。

**Instructionsテンプレート**（そのままエージェントのInstructionsに貼り付けてください）:

```
あなたは KJ法支援の候補生成器です。あなたの出力は提案であり確定しません。

以下の指示に必ず従ってください。
- 点数・順位・％・優先度の数値を付けないでください。
- 曖昧・対立・未確定はそのまま保持して提示してください。
- 出典のない断定をしないでください。
- 入力にタスクシートが含まれる場合、応答はタスクシート内の「応答契約」で示された agent-response.v1 の JSON のみで返してください。説明文・前置きは不要です。
- タスクシートの「相関ブロック」全体を応答の correlation にそのまま入れ、taskId も必ず一致させてください。
```

**逸脱時リカバリ定型文**（エージェントが説明文付きで返してきた場合や、JSONが壊れている場合に、そのまま貼り付けて再依頼してください）:

```
直前の応答を、説明文を除き agent-response.v1 スキーマの JSON のみで再出力してください。元のタスクシートの相関ブロック全体を correlation にそのまま入れ、taskId も一致させてください。
```

相関情報が不完全な旧形式も互換モードでは解析できますが、「由来未検証」と表示します。厳格モードでは受け付けません。

ナレッジベースを追加する必要はありません。文脈は毎回タスクシートで渡すため、エージェントに事前知識を登録する必要もありません。組織の用語集を追加するかどうかは任意です。

## データ境界チェックリスト

タスクシートにはSafeModeを適用し、人間が確認した範囲の情報だけを載せます。ただし、**外部エージェント側でのデータの取り扱い（テナントの区分、ログの保存、学習への利用）は、組織のライセンス・契約・設定によって異なります**。エージェントを利用する前に、運用担当者は次の事項を確認してください。

- [ ] 利用するエージェント基盤が、組織のテナント境界内で動作することを確認したか。
- [ ] 入力（タスクシート）や出力（応答）が、意図しない期間ログとして保持されないか確認したか。
- [ ] 入力データがモデルの追加学習に使われない設定になっているか確認したか（組織の契約条件による）。
- [ ] タスクシートを貼り付ける前に、SafeModeが意図した状態（既定ON）であることを確認したか。
- [ ] 応答を取り込む前に、出典参照や未レビュー本文が意図せず含まれていないか（書き出し時の設定）を確認したか。

## トラブルシュート

**JSONに誤りがある（説明文が混ざる、コードブロックが閉じていないなど）**: 上記の「逸脱時リカバリ定型文」を使って、出力を再依頼してください。「応答を取り込む」の解析結果には、エラー内容が具体的に表示されます。

**渡す情報が多すぎる**: 選択するカードや島の数を減らし、タスクシートを分割してください。依頼の種類を1つに絞ることも、文脈を短くする助けになります。

**応答の一部だけ取り込みたい**: 「応答を取り込む」では、提案ごとに「取り込む」か「破棄する」かを選べます。すべてを取り込む必要はありません。

**参照先のカードや島が見つからないと表示される**: タスクシートを書き出した後に、カードや島を削除するなど、文書を変更した場合に起こります。提案は破棄されず「孤立提案」として保持表示されるので、内容を確認してから改めて破棄するか、対象を作り直してから再依頼してください。

## 関連 API

- `POST /docs/{id}/export-audit`（タスクシート書き出しの記録）
- `POST /ai/external-tasks/register`（本文を含まないタスク相関の登録。失敗時は書き出しを中止）
- `POST /ai/external-proposals/register`（本文を含まない外部提案指紋の登録）
- `POST /ai/external-proposals/audit`（外部提案の採否記録。成功後だけ文書へ反映）
- `POST /ai/proposals/audit` はアプリ内生成提案専用であり、外部提案には使用しません。

APIの詳細は実装と設計の正本を参照してください。本書では、利用者と運用担当者の手順、およびデータの取り扱いに関する確認事項を説明します。
