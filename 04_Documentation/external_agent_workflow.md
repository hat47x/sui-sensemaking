# 外部エージェント連携ワークフロー（Copilot 等・定額課金 AI）

対象読者: 定額課金のAIエージェント（Microsoft Copilot / Copilot Studio、ChatGPT Enterprise等）に思考の一部を委ねたい利用者、Copilot Studio等でエージェントを構成する運用者。

目的: sui-sensemakingから「エージェントへ依頼」で書き出したタスクシートをエージェントへ渡し、返ってきた応答を「応答を取り込む」へ貼り付けて未レビューの提案として取り込むまでの、追加開発なしで再現できる手順を説明します。

範囲外: Copilot Studioテナントの構築・管理（Microsoft公式の手順に従ってください）。

読後にできること: タスクシートの書き出しから応答の取り込みまでを自分の手で再現でき、エージェント基盤側で確認すべきデータ境界を判断できます。

## 基本方針

- sui-sensemakingは外部のエージェントと直接通信しません。書き出し・取り込みは、常に人間がタスクシートやJSONをコピー&ペースト（またはファイル添付）する明示操作です。
- エージェントの出力は常に「AI由来・未レビューの提案」です。取り込んだだけでは文書は変わりません。採用するかどうかは人間が個別に判断します。
- 応答に点数・順位・確度などの数値評価が含まれていても、取り込み時に無視（破棄）されます。エージェントに「採点」を期待する使い方は想定していません。
- 書き出しは既存の共有・書き出し境界（SafeMode・共有前確認）を、取り込みはインポートの信頼境界（検証とサニタイズ）を、必ず通過します。

## 最短運用（追加構築なし）

Copilotなどのチャット欄にそのまま貼り付けるだけで使えます。

1. sui-sensemakingでカードや島を選択し、「詳細」表示を有効にしてから「エージェントへ依頼」を開きます。
2. 依頼の種類（島のタイトル候補・統合できそうな組の候補・文章の草稿・対立する視点・違和感の指摘・自由な分析）を選び、書き出す範囲を確認してタスクシート（.md）をダウンロードまたはコピーします。
3. Copilotのチャットにタスクシートを貼り付け（またはファイルを添付）ます。
4. 返ってきたJSON（コードフェンス付き）をコピーし、sui-sensemakingの「エージェント応答を取り込む」に貼り付けます。
5. 解析結果（受理件数・警告件数）を確認し、提案ごとに「取り込む」または「破棄する」を選びます。取り込んだ提案は未レビューの状態で反映され、Cmd/Ctrl+Zで個別に取り消せます。

## エージェント化する場合（推奨・再現性向上）

毎回チャットで説明し直す代わりに、Copilot Studio等でエージェントを1つ構成しておくと、同じ手順を再現しやすくなります。

**Instructionsテンプレート**（そのままエージェントのInstructionsに貼り付けてください）:

```
あなたは KJ法支援の候補生成器です。あなたの出力は提案であり確定しません。

以下の指示に必ず従ってください。
- 点数・順位・％・優先度の数値を付けないでください。
- 曖昧・対立・未確定はそのまま保持して提示してください。
- 出典のない断定をしないでください。
- 入力にタスクシートが含まれる場合、応答はタスクシート内の「応答契約」で示された agent-response.v1 の JSON のみで返してください。説明文・前置きは不要です。
- タスクシートの「相関ブロック」全体を応答の correlation にそのまま入れ、taskId も必ず一致させてください。
```

**逸脱時リカバリ定型文**（エージェントが説明文付きで返してきた場合や、JSONが壊れている場合に、そのまま貼り付けて再依頼してください）:

```
直前の応答を、説明文を除き agent-response.v1 スキーマの JSON のみで再出力してください。元のタスクシートの相関ブロック全体を correlation にそのまま入れ、taskId も一致させてください。
```

完全な相関情報がない旧形式も互換モードでは解析できますが、「由来未検証」と表示されます。厳格モードでは拒否されます。

ナレッジベースの追加は不要です。文脈は毎回タスクシートで供給されるため、エージェント側に事前知識を持たせる必要はありません（組織用語集を追加する運用は任意です）。

## データ境界チェックリスト

タスクシートに載る内容はSafeMode適用済み・人間確認済みの範囲のみですが、**エージェント基盤側のデータの扱い（テナント境界・ログ保持・学習利用設定）は、組織のライセンス・契約・設定に従います**。エージェントを利用する前に、運用者は次を確認してください。

- [ ] 利用するエージェント基盤が、組織のテナント境界内で動作することを確認したか。
- [ ] 入力（タスクシート）や出力（応答）が、意図しない期間ログとして保持されないか確認したか。
- [ ] 入力データがモデルの追加学習に使われない設定になっているか確認したか（組織の契約条件による）。
- [ ] タスクシートを貼り付ける前に、SafeModeが意図した状態（既定ON）であることを確認したか。
- [ ] 応答を取り込む前に、出典参照や未レビュー本文が意図せず含まれていないか（書き出し時の設定）を確認したか。

## トラブルシュート

**JSONが壊れて返ってくる（説明文が混ざる、コードフェンスが欠ける等）**: 上記の「逸脱時リカバリ定型文」を使って再依頼してください。「応答を取り込む」の解析結果には、エラー内容が具体的に表示されます。

**文脈が長すぎて依頼しづらい**: 書き出す範囲（選択するカード・島の数）を絞って、タスクシートを分割してください。依頼の種類を1つに絞ることも、文脈を短くする助けになります。

**応答の一部だけ取り込みたい**: 「応答を取り込む」では提案ごとに個別に取り込む/破棄するを選べます。全件を一度に取り込む必要はありません。

**参照先のカードや島が見つからないという表示が出る**: 文書がタスクシート書き出し後に変わった（カードや島を削除した等）場合に起こります。提案は破棄されず「孤立提案」として保持表示されるので、内容を確認してから改めて破棄するか、対象を作り直してから再依頼してください。

## 関連 API

- `POST /docs/{id}/export-audit`（タスクシート書き出しの記録）
- `POST /ai/external-tasks/register`（本文を含まないタスク相関の登録。失敗時は書き出しを中止）
- `POST /ai/external-proposals/register`（本文を含まない外部提案指紋の登録）
- `POST /ai/external-proposals/audit`（外部提案の採否記録。成功後だけ文書へ反映）
- `POST /ai/proposals/audit` はアプリ内生成提案専用であり、外部提案には使用しません。

APIの詳細は実装と設計正本を参照してください。この文書では、利用者・運用者向けの手順とデータ境界の確認だけを説明します。
