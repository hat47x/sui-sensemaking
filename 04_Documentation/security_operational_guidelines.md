# セキュリティ運用ガイドライン

想定読者: sui-sensemakingの安全に関わる設定を確認する管理者、運用担当者、セキュリティ担当者。

本書では、SafeMode、AIへの接続、監査記録の連携、共有と書き出しの設定を変更する前に、最低限確認すべき事項を説明します。

## 基本姿勢

- 迷ったら、設定を変えずに保留する。
- 外部サービスと共有する理由を説明できないときは、共有しない。
- SafeModeを緩めるかどうかは、便利さではなく、必要性と元に戻せるかで判断する。
- AIの出力は提案として扱い、人間が確認するまで、確定した状態にしない。
- APIキー、トークン、パスワード、加工していない顧客情報は、ログ、スクリーンショット、書き出しに含めない。

## 役割の考え方

ここで示す役割は、組織の正式な肩書と一致していなくても構いません。重要なのは、少なくとも次の三つの責務を区別することです。

| 責務 | 確認すること |
| --- | --- |
| 安全性を判断する人 | 秘密情報、外部サービスとの共有、SafeModeを緩めるリスク |
| 業務上の必要性を判断する人 | なぜ変更が必要か、利用者にどのような影響があるか |
| 設定を実行する人 | 変更の内容、元に戻す方法、確認した結果 |

同じ人が複数の役割を兼ねる場合も、誰が判断し、誰が実行したかは記録で区別します。組織が承認の期限や人数について、より厳格な規程を定めている場合は、それを優先してください。

## 実行プロファイルとセキュリティの判断

設定を変更する前に、どの運用プロファイルを使うか決定します。プロファイルの詳細は、GitHub上の [runtime_parameter_registry.md](https://github.com/hat47x/sui-sensemaking/blob/main/02_Architecture/runtime_parameter_registry.md) を参照してください。

- `local-dev`: 外部との共有を避けた、最初の検証向けです（`SUI_LLM_PROVIDER=none`）。
- `evaluation`: Composeでの評価向けです。外部連携は、必要なときだけ、限定して有効にします。
- `enterprise-production`: 厳格な運用を前提に、`SUI_ALLOW_JIT_PROVISIONING=false` を標準とします。
- `enterprise-production`: `SUI_ACCESS_CONTROL_FAIL_SAFE_MODE` は、`read_only` か `deny` のどちらにするかを事前に合意し、運用中に暗黙のうちに変えません。

運用プロファイルが決まるまでは、`SUI_ALLOW_JIT_PROVISIONING`、`SUI_AUDIT_*`、`SUI_ACCESS_CONTROL_*`を変更しないでください。

## 設定を変える前の確認

設定を変更する前に、次の四点を簡潔に説明できるようにします。

| 確認 | 例 |
| --- | --- |
| 何を変えるか | `SUI_LLM_PROVIDER`、監査ログのHTTPエンドポイント、アクセス制御のアダプタ |
| なぜ必要か | 検証、障害調査、組織内のLLMとの連携 |
| 何を共有するか | LLMへの入力、監査イベント、書き出したファイル、ログ |
| 元に戻せるか | 元の環境変数、再起動の手順、確認のコマンド |

四点のうち説明できないものがあれば、設定変更を保留してください。

## 判断を支援する例

以下は判断の規則ではなく、確認すべき事項の例です。

### ローカルLLMを使う

次の事項を確認します。

- 実際の接続先が、ローカル、または組織内で管理されたエンドポイントである。
- 入力に、秘密情報や未公開の顧客情報を含めない運用になっている。
- 失敗したときに、`SUI_LLM_PROVIDER=none` に戻せる。

次の場合は判断を保留します。

- 名前に「local」が含まれていても、接続先が外部ネットワーク上にある。
- 送信する情報の保存期間や、別の目的への利用条件を確認できない。

### 大規模LLMを使う

次の事項を確認します。

- 明示的な同意によって利用を有効にしている。
- 許可リストに登録した接続先と、実際に接続するホストが一致している。
- 外部サービスと共有する理由と、共有する情報の範囲が、記録されている。

次の場合は判断を保留します。

- 許可リストとホストが一致しない。
- 未レビューの情報や秘密情報が共有されるおそれが、残っている。

### 監査ログのHTTP連携を使う

次の事項を確認します。

- 接続先、保持期間、所有者が分かっている。
- ペイロードに秘密情報を含めない方針がある。
- SafeMode中に連携を許可するときは、その理由を記録している。

次の場合は判断を保留します。

- 監査記録の接続先について、管理者や保存期間が分からない。
- 障害時に、待ち行列、処理時間の上限、再送をどのように扱うか分からない。

## 記録に残す最小の項目

- 変更した日時
- 対象の環境
- 変更した設定
- 判断した人、または役割
- 実行した人、または役割
- 元に戻す方法
- 確認した結果

組織固有の承認番号、個人情報、秘密情報、内部のURLは、公開文書や共有用のメモに含めません。

## 確認のコマンド

```bash
curl -fsS http://localhost:8080/api/healthz
docker compose logs api --tail=100
```

APIキーを有効にしているときは、次のようにします。

```bash
curl -H "X-API-Key: <key>" http://localhost:8080/api/docs/<doc_id>
```
