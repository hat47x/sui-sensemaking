# 受け入れ確認

対象読者: sui-sensemakingを起動したあと、画面から主要操作を確認したい利用者、運用担当者、評価担当者。

目的: マウスとキーボードで基本操作が自然に行えるか、保存や共有前確認ができるかを、短い手順で確認します。

初めて利用価値を体験する場合は、先に[最初の意味ある配置を作る](getting_started.md)を使ってください。教程は1本の学習経路で、この文書は、変更後や評価のときに使う、手動のスモークテストです。

## 確認前の準備

標準構成で起動し、APIが応答することを確認します。

```bash
cd 03_Implement/deploy
docker compose up --build -d
curl -fsS http://localhost:8080/api/healthz
```

次にブラウザで `http://localhost:8080` を開きます。Dockerを使わない起動方法は [導入手順](installation.md) を参照してください。

標準サンプルの `doc_phase1_canvas` は、サーバーにあらかじめ保存されているわけではなく、初めてブラウザで画面を開いたときに、frontendが自動で作成します。そのため、初めて表示する前に標準サンプルのAPIを確認すると、404になります（異常ではありません）。一度画面を開いたあとなら、次のように、標準サンプルが保存されていることを確認できます。

```bash
curl -fsS http://localhost:8080/api/docs/doc_phase1_canvas
```

この確認で、`Internal Server Error`（5xx）や接続の失敗が表示されたときは、まず、backendが起動しているかを確認します。Dockerを使わないときは、frontendだけでなくbackendも別の端末で起動し、一度画面を開いたうえで、`http://127.0.0.1:<frontendのポート>/api/docs/doc_phase1_canvas` が応答することを確認してください。

## 画面全体を見る

起動後は、ヘッダー、キャンバス、右側パネルが見えることを確認します。ヘッダーにはSafeMode、表示、検索、共有と再現、保存などの主要操作があります。

![起動後の標準画面](assets/screenshots/app-canvas-overview.png)

> すべてのUI要素の現行スクリーンショット（ヘッダー詳細、カードのバッジ、右クリックメニュー、作業モード面、共有前確認、レスポンシブ各幅など）は [現行UIカタログ](ui_catalog.md) にまとめています。

## 通常表示と詳細表示を見分ける

通常表示では、文書を開く、カードを作る、島を作る、選択内容を削除する、保存する、表示を切り替える、共有前に確認する、といった基本操作が先に見えます。AIによる提案、差分確認、パッチ、診断などは「詳細」を選ぶまで表示されません。

次の順に確認します。

1. 画面を開いた直後に、「新規カード」「島を作成」「削除」「保存」がヘッダーに見える。
2. 「詳細」が選択されていない状態では、AIによる提案などの高度な操作が常設されていない。
3. 「詳細」を選ぶと高度な操作が表示され、もう一度「詳細」を選ぶと通常表示へ戻る。
4. 通常表示へ戻ったあとも、カードの作成、選択、保存を続けられる。

「詳細」を使わなくても、カードを書く、並べる、束ねる、つなぐ、保存するという基本作業は完了できます。通常表示に高度な操作が増えて基本操作を探しにくい場合や、「詳細」を閉じても元の表示へ戻れない場合は、問題として記録してください。

## マウスで確認すること（LLMが不要な手動の操作）

既定（`SUI_LLM_PROVIDER=none`）のままでも、次の手動の操作だけで、「書く、並べる、束ねる、つなぐ」が完結します。AI機能は使いません。

1. 「新規カード」ボタン、または背景を右クリックして「ここに新規カード」でカードを追加する。追加直後はそのまま本文を入力できる。
2. カードをダブルクリックして本文を編集する（Enterまたは入力欄の外をクリックで確定、Escで取消、Shift+Enterで改行）。
3. カードを選択し、キャンバス上で移動する。右側パネルの先頭に「現在の選択」が表示され、対象・レビュー状態・次の操作が分かることを確認する。
4. カードを右クリックし、「編集／関係線でつなぐ／島を作成／削除」が選べることを確認する。
5. 複数カードを選択して「島を作成」ボタン、またはカード右クリックの「島を作成」で島を作り、右側パネルの情報が更新されることを確認する。
6. カードを島の領域までドラッグして離し、その島に追加されること（元に戻すは1回）を確認する。
7. 島を右クリックして「サイズ変更／形状編集」を選び、現れた頂点ハンドルをドラッグして島の大きさ・形を調整する。「選択カードをこの島に追加」「島を削除」も確認する。
8. 「削除」ボタン、またはカード/島の右クリックの削除で、選択を削除できることを確認する。
9. ヘッダーの「ファイル」「編集」メニュー、「詳細」トグル（AI・高度機能の表示切替）、`表示`、`共有と再現` を開いて状態を確認する。「詳細」を選ぶまで、右側パネルの詳細な絞り込みやガイド付きフローが常設されないことを確認する。
10. 保存し、ページを再読み込みして変更が残っていることを確認する。

カードを選択した直後は、キャンバス上の選択枠だけでなく、右側パネルの「現在の選択」でも対象を確認します。レビュー状態が「未レビュー」の場合は、共有や書き出しの前に内容を見直してください。

カードまたは島に違和感を残す場合は、「近すぎる」「遠すぎる」「同じものではない」「違和感がある」「理由は言葉にできない」から当てはまるものを選び、必要ならメモを加えます。理由をうまく説明できない場合も記録できます。「再提案を確認」を選ぶと詳細表示が開き、再提案の作業面へ移動します。AIを無効にした構成でも違和感は文書に保存されますが、再提案候補は生成されません。

![カード選択時の現在の選択パネル](assets/screenshots/selection-context-card.png)

操作中に、ボタンやパネルが見切れる、隣の操作を覆う、押した後の結果が分からない、という状態があれば記録してください。

## キーボードで確認すること

1. `Tab` でヘッダー、キャンバス操作、右側パネルへ移動できることを確認する。
2. フォーカス中のボタンを `Enter` または `Space` で実行できることを確認する。
3. `表示` や `共有と再現` のパネルを開いたあと、次に操作すべき項目へ自然に移動できることを確認する。
4. 文字入力欄では、入力、削除、保存または反映の流れが分かることを確認する。
5. 操作をやめたいときに、キャンセル、閉じる、または別の場所への移動で自然に戻れることを確認する。

キーボードだけで主要操作に届かない場合や、同じ名前の操作が複数出て迷う場合は、画面の使いやすさの課題として記録してください。

## スクリーンリーダーで確認すること

NVDA、JAWS、VoiceOverなど手元のスクリーンリーダーを使い、開始、編集、保存、共有前確認の流れが音声だけで分かるかを確認します。

1. 画面を開いた直後、見出しへ移動する機能で、プロダクト名の見出し（`h1`）へ到達できることを確認する。
2. 「新規カード」でカードを追加した直後、本文入力欄にフォーカスがあることが読み上げられ、確定操作のあと入力した内容が反映されたと分かることを確認する。
3. カードを選択し、右側パネルの「現在の選択」が自動的に読み上げられ、対象の種別、保留・違和感の有無、レビュー状態、根拠の順で聞こえることを確認する（選択のたびに手動でパネルへ移動しなくても内容が分かることを見る）。
4. 「詳細」を開いたあとの作業モードタブへ移動し、タブとして認識されること、矢印キーまたは `Home`/`End` で移動できること、選択中のタブ名が読み上げられることを確認する。
5. 「共有と再現」を開き、「出典参照を含める」トグルにフォーカスすると説明文が続けて読み上げられ、ONにしたときの警告文も読み上げられることを確認する。
6. 凡例を開いたときに対話であることと名前が読み上げられ、`Escape` で閉じたあと元のボタンへフォーカスが戻ることを確認する。

見出し・読み上げ順・フォーカス移動のいずれかが期待どおりでない場合、または操作の途中で今どこにいるか分からなくなる場合は、画面の使いやすさの課題として記録してください。

## 表示幅を変えて確認する

画面崩れを確認するときは、少なくとも次の幅を見ます。

| 幅 | 目的 |
| --- | --- |
| 1440px | 標準的なデスクトップ |
| 960px | 狭めのデスクトップとタブレット |
| 768px | タブレット相当。右側のパネルと共有パネルの見切れを確認する |
| 390px | スマートフォン相当 |

すべての細部を見る必要はありません。主要操作が見えるか、テキストが重ならないか、保存できるかを優先します。

390pxでは、ヘッダーが複数行に折り返され、検索、表示、共有と再現、保存などの主要操作が画面外へ消えないことを確認します。

![390pxの幅でのヘッダーの確認](assets/screenshots/mobile-toolbar-smoke-390.png)

## 大きな文書で確認する

カードや島が多い文書では、表示の重さよりも「操作を続けられるか」を優先して確認します。

1. 検索欄に一部のカード本文を入力し、該当カードが見つかることを確認する。
2. 検索結果を選択し、右側パネルの情報が現在の選択に追従することを確認する。
3. `表示` を開き、表示モードや絞り込みを変えても、パネルが画面外に見切れないことを確認する。
4. `共有と再現` を開き、共有前チェック、SafeMode、出力形式が読めることを確認する。
5. 診断またはレビューパックの書き出しを実行し、処理中表示とキャンセルが使えることを確認する。

大きな文書では、すべてのカードを目視確認する必要はありません。検索、選択、表示切替、共有前確認、処理中表示の5点が途切れないことを見ます。

## 共有や書き出しの前に確認すること

共有やレビューパックの書き出しを使う場合は、[データ取り扱い](data_handling.md) のチェックリストに沿って、出力に秘密情報や内部メモが混ざっていないことを確認します。受け入れ確認では、「共有と再現」を開き、`共有前チェック` にSafeMode、公開範囲、未レビュー情報、出力形式が表示されることを確認します。

![共有と再現パネルの書き出しと共有前のチェック](assets/screenshots/share-export-safe-mode.png)

未レビュー・違和感・矛盾のいずれかを含む文書で「レビューパックを書き出す」を押すと、書き出しの直前に確認画面（共有直前サマリ）が表示されます。件数（評価語やスコアではなく所在の提示のみ）と「既定で非表示になります」という説明を確認し、「戻って確認する」で編集に戻るか、「続行する」で書き出しを進められることを確かめます。3種の件数がすべて0件の文書では、この確認画面は表示されず書き出しがそのまま進みます。

「出典参照を含める」トグル（既定OFF）をONにすると、原データへの参照（インタビュー記録の所在など）が共有先に渡る旨の警告が表示されることを確認します。

## 処理中表示とキャンセルを確認すること

診断やレビューパックの書き出しは、文書の大きさやブラウザ環境によって時間がかかることがあります。受け入れ確認では、処理が長くなった場合でも次の状態が分かることを確認します。

1. 画面に「処理中」であることと、いま何をしているかが表示される。
2. 同じ処理を重ねて実行できないように、実行中のボタンが無効になる。
3. 操作をやめたいときに、キャンセルボタンで中止できる。
4. 中止したあと、画面上に「中止した」ことが分かるメッセージが残る。
5. 390px程度の狭い画面でも、進捗や中止メッセージが画面外にはみ出さない。

## 問題を記録するとき

次の情報があると、再現と修正がしやすくなります。

- 対象URL
- ブラウザ名
- 画面幅
- 操作手順
- 期待した結果
- 実際の結果
- 可能ならスクリーンショット

ログやスクリーンショットを共有するときは、APIキー、トークン、パスワード、加工していない顧客情報を含めません。どこまで残すか迷うときは [データ取り扱い](data_handling.md) を確認してください。

## 確認記録のまとめ方

受け入れ確認を実施したら、次の4点を最低限記録します。

- 確認した日時と対象環境。
- 確認した画面幅とブラウザ。
- 実施した操作と結果。
- 問題があった場合の再現手順、スクリーンショット、次に確認すべきこと。

画面上で何を確認し、何が期待どおりで、何が期待と違ったかが分かるように記録します。

## 操作感の確認観点

画面操作を確認するときは、機能の有無だけでなく、次の流れが自然かも見ます。

- 開始: どこから操作を始めればよいか分かる。
- 選択: カード、島、表示、共有などの対象を迷わず選べる。
- 表示: 選択した結果や状態が画面内で確認できる。
- 閉じる: パネルやメニューを閉じる方法が分かる。
- 復帰: 操作をやめたあと、元の作業へ戻れる。

`Escape` で閉じる、`Tab` で次の操作へ進む、`Enter` や `Space` でボタンを実行する、といった基本操作も合わせて確認します。マウスだけ、またはキーボードだけで操作したときに流れが途切れる場合は、問題として記録してください。

## 確認結果の判定

受け入れ確認の結果は、次の3つに分けて残します。

- **問題なし**: 主要操作が期待どおりに完了し、次の作業へ進める。
- **注意あり**: 操作は完了するが、表示の分かりにくさ、待ち時間、軽微な崩れがある。
- **停止**: 保存できない、共有前確認ができない、SafeMode状態が分からない、主要操作が画面外に見切れる。

「停止」に該当する場合は次工程へ進まず、再現手順、影響範囲、再確認に必要な条件を記録します。
