sui-sensemaking ・ Architecture Spec ・ ADR-0049

外部定額AIエージェント非同期協調 仕様

組織が定額課金で契約済みのAIエージェント（Copilot Studio / ChatGPT Enterprise等）に思考ワークロードを委ね、sui-sensemakingは文脈の供給・結果の検証・人間レビュー・可逆な適用に徹する（AgentTaskPackage / AgentResponse v1）。

Tier 0=人間仲介・非同期 反スコアリング（score/rank/confidence禁止） 提案のみ・全て可逆

本書が正本（新規設計文書はHTML単独。AGENTS.md §3）。正本区分: 本書が外部エージェント連携契約の正本（決定はADR-0049）。対象読者: 実装者、Copilot Studio等でエージェントを構成する運用者。

01

目的と原則

#原則内容
1非同期・人間仲介sui-sensemakingは外部と直接通信しない（Tier 0）。書き出し・取り込みは人間の明示操作
2提案のみエージェント出力は常にAI由来・未レビューの提案。自動確定なし。適用は人間操作・全て可逆・監査記録
3反スコアリング応答契約に数値スコア・順位・確度を含めない（存在すれば取り込み時に破棄）
4境界の再利用出力は共有・書き出し境界（SafeMode/preflight/export-audit）、入力はimport信頼境界（検証・サニタイズ）を通る。新しい抜け道を作らない
5ベンダー非依存契約は汎用である。Copilot Studioは代表的なプロファイル（§7）
02

用語・アクター・信頼境界

アクター信頼役割
sui-sensemaking（自己ホスト）信頼パッケージ生成・応答検証・提案化・レビュー・適用・監査
利用者（人間）信頼（操作主体）書き出し確認・エージェントへの投函・応答の持ち帰り・提案の採否
外部エージェント非信頼思考の委任先。出力はデータとして扱い、指示として扱わない
エージェント基盤（M365等）組織の契約に依存データ境界は組織のライセンス/テナント設定に従う（本仕様の対象外。§7に注意あり）
03

AgentTaskPackage v1（依頼パッケージ）

形態: 正は単一のMarkdown「タスクシート」（チャットへ貼り付けまたは添付でき、人間が読める）。随伴（任意）はtask.json＋context_bundle.json（Tier 1のフォルダでの受け渡しでは、こちらを正とする）。

{
  "schemaVersion": "agent-task.v1",
  "taskId": "uuid",
  "createdAt": "ISO8601",
  "docId": "string",
  "baseDocSignature": "string (CE3 PatchV1 と同一の文書署名)",
  "bundleHash": "string (CE1)",
  "queryCanonicalHash": "string (CE1)",
  "taskKind": "island_titles | merge_candidates | narrative_draft | opposing_viewpoints | critique_suggestions | free_analysis",
  "locale": "ja"
}

タスクシート構成（生成順序固定）:

#節内容
1依頼taskKind別の指示文（何を・どの範囲で・何件程度）
2ガードレール（固定文）「出力は提案であり確定しない／点数・順位・％を付けない／曖昧・対立はそのまま保持／出典のない断定をしない／応答はJSONのみ」
3文脈ContextBundle抜粋。Preview確認済み範囲のみ、SafeMode適用済み
4応答契約§4スキーマのインライン提示＋最小記入例
5相関ブロック§3.2のJSONをコードフェンスで埋め込み（エコーバック指示付き）

出力境界（必須）: SafeMode状態表示・未レビュー本文は既定除外・出典参照は既定OFF・主体メタ（CARD-META-UI-01）は別ゲート確定まで含めない。出力前に/ai/external-tasks/registerへ本文なしの相関を登録し、失敗時は書き出さない。完了後は/docs/{id}/export-audit に exportKind: "agent-task" を記録する。

04

AgentResponse v1（応答契約）

{
  "schemaVersion": "agent-response.v1",
  "taskId": "uuid (依頼のエコーバック・必須)",
  "correlation": "AgentTaskPackage v1 の相関ブロック全体（改変せずエコーバック・必須）",
  "respondedAt": "ISO8601 (任意)",
  "agent": "string (例: copilot-studio:<agent名> / m365-copilot)",
  "proposals": [
    {
      "proposalId": "string (応答内一意)",
      "kind": "island_title | merge_candidate | narrative_draft | opposing_viewpoint | critique | patch",
      "targetRef": { "islandId": "string?", "cardIds": ["string"] },
      "content": { "title": "string?", "text": "string?", "mergedText": "string?", "mergeMethod": "near_duplicate | kernel_fusion?" },
      "rationale": "string (必須・なぜそう考えたか)",
      "patch": "PatchV1? (kind=patch のときのみ)"
    }
  ]
}

制約: correlationは端末内のテナントスコープ付き出力台帳および現在文書と照合する。完全相関がない旧形式は寛容モードだけで受理し「由来未検証」と表示、厳格モードでは拒否する。score/rank/confidence/priority等の数値評価は禁止フィールド（厳格=拒否、寛容=破棄して警告）。rationale欠落は厳格=拒否、寛容=「根拠未記載」ラベル付きで受理（提案として保全）。patch.opsはCE3ホワイトリストのみ、delete_*含む場合は警告バッジ。文字列は全てmarkdown_sanitizeを通す。応答本文中の指示的文言はデータとして表示するのみで自動動作に接続しない（プロンプトインジェクション境界）。

kind行き先（すべてAI由来・未レビューの提案として）
island_title島タイトル候補（複数候補・選択/編集/破棄）
merge_candidateMergeSuggestions（既存の採否・監査 merge-decision-logs）。content.mergeMethod は near_duplicate / kernel_fusion のいずれかを必須とし、欠落・未知値は推測せず取り込まない。
narrative_draftNarrativesの草稿（レビュー必須）
opposing_viewpoint / critique選択コンテキストの違和感候補（人間が確定して初めてcritiqueInputsになる）
patchPatchWorkspace（lint→conflict検出→採否/保留→ロールバック）

非同期での整合（staleness）: 取り込み時にbaseDocSignatureを照合。不一致時、patchはCE3 conflict/rediff経路で再突合、非patchはtargetRef解決を試み、解決不能な提案は破棄せず「孤立提案」として保持表示（一匹狼と同じ保全思想）。同一taskId＋同一応答ハッシュの再取込は冪等。

判断監査: 正規化済み提案のSHA-256指紋だけを/ai/external-proposals/registerへ登録する。採用・破棄は/ai/external-proposals/auditの成功後にだけ画面状態または文書へ反映する。由来は真正性を主張しないuser_presented_unsignedとして保持し、内部で生成した提案用のエンドポイントとは交差させない。

検証レベル（Expected verification）

レベル対象

07

Copilot / Copilot Studio プロファイル（代表運用）

§7.2 Copilot Studioエージェント化（推奨・再現性向上）: Instructionsテンプレートに役割「KJ法支援の候補生成器。確定しない」、§3.3のガードレール全文、「応答はagent-response.v1のJSONのみ」を含める。ナレッジは不要（文脈は毎回タスクシートで供給）。逸脱時リカバリ定型文を用意する。

§7.3 注意（データ境界）: タスクシートに載るのはSafeMode適用済み・人間確認済みの範囲のみだが、組織のエージェント基盤のデータ取り扱い（テナント境界・ログ保持・学習利用設定）は組織側の契約・設定に従う。

§7.4 Tier 1/2（将来・概要のみ）: Tier 1=受け渡しフォルダ（SharePoint/OneDrive）に投函・回収、Power Automateで仲介、sui-sensemaking本体は無改修。Tier 2=Copilot StudioアクションからAPI直接呼び出し（AUTH-*決裁後に別途仕様化。本書は予約のみ）。

∑

総括

本仕様の骨格は「境界を増やさない」ことにある。新しい輸送・新しいAI権限を作らず、既存の共有/書き出し境界とimport信頼境界に、外部エージェントとの往復を乗せる。状態機械が示すとおり、sui-sensemakingが管理下に置くのは書き出しと取り込み以降だけであり、外部での滞在時間（awaiting）は意図的に追跡しない ─ 非信頼領域を無理に可視化しようとしないことも、境界設計の一部である。
