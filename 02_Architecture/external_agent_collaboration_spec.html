sui-sensemaking ・ Architecture Spec ・ ADR-0049

外部定額AIエージェント非同期協調 仕様

組織が定額課金で契約済みのAIエージェント（Copilot StudioやChatGPT Enterpriseなど）に思考にかかる作業を委ね、sui-sensemakingは文脈の供給・結果の検証・人間レビュー・可逆な適用に徹する（AgentTaskPackageとAgentResponse v1）。

Tier 0は人間が仲介する非同期方式 反スコアリング（score、rank、confidenceを禁止） 提案のみ・全て可逆

本書が正本である（新規設計文書はHTML単独とする。AGENTS.md §3）。正本の区分としては、本書が外部エージェント連携契約の正本であり、決定はADR-0049にある。対象読者は、実装者と、Copilot Studioなどでエージェントを構成する運用者である。

01

目的と原則

#原則内容
1非同期・人間仲介sui-sensemakingは外部と直接通信しない（Tier 0）。書き出しと取り込みは、人間の明示的な操作で行う
2提案のみエージェントの出力は常に、AI由来で未レビューの提案として扱う。自動では確定しない。適用は人間の操作で行い、すべて可逆とし、監査に記録する
3反スコアリング応答契約に数値スコア・順位・確度を含めない（含まれていた場合は取り込み時に破棄する）
4境界の再利用出力は共有・書き出し境界（SafeMode、preflight、export-audit）を通り、入力は取り込みの信頼境界（検証とサニタイズ）を通る。新しい抜け道は作らない
5ベンダー非依存契約は汎用である。Copilot Studioは代表的なプロファイル（§7）
02

用語・アクター・信頼境界

アクター信頼役割
sui-sensemaking（自己ホスト）信頼パッケージ生成・応答検証・提案化・レビュー・適用・監査
利用者（人間）信頼（操作主体）書き出し確認・エージェントへの投函・応答の持ち帰り・提案の採否
外部エージェント非信頼思考の委任先。出力はデータとして扱い、指示として扱わない
エージェント基盤（M365等）組織の契約に依存データ境界は組織のライセンスとテナントの設定に従う（本仕様の対象外。§7に注意あり）
03

AgentTaskPackage v1（依頼パッケージ）

形態　正本は単一のMarkdown「タスクシート」で、チャットに貼り付けるか添付でき、人間が読める。任意の随伴ファイルとしてtask.jsonとcontext_bundle.jsonを付ける。Tier 1のフォルダでの受け渡しでは、随伴ファイルを正本とする。

{
  "schemaVersion": "agent-task.v1",
  "taskId": "uuid",
  "createdAt": "ISO8601",
  "docId": "string",
  "baseDocSignature": "string (CE3 PatchV1 と同一の文書署名)",
  "bundleHash": "string (CE1)",
  "queryCanonicalHash": "string (CE1)",
  "taskKind": "island_titles | merge_candidates | narrative_draft | opposing_viewpoints | critique_suggestions | free_analysis",
  "locale": "ja"
}

タスクシートの構成（生成順序は固定）

#節内容
1依頼taskKindごとの指示文（何を、どの範囲で、何件程度か）
2ガードレール（固定文）「出力は提案であり確定しない／点数・順位・％を付けない／曖昧・対立はそのまま保持／出典のない断定をしない／応答はJSONのみ」
3文脈ContextBundleの抜粋。Preview確認済みの範囲だけを含め、SafeModeを適用済みとする
4応答契約§4のスキーマをそのまま載せ、最小の記入例を添える
5相関ブロック§3.2のJSONをコードフェンスで埋め込み、エコーバックの指示を付ける

出力境界（必須）　SafeModeの状態を表示し、未レビューの本文は既定で除外し、出典参照は既定でOFFとし、主体メタ（CARD-META-UI-01）は別ゲートが確定するまで含めない。出力前に/ai/external-tasks/registerへ本文なしの相関を登録し、失敗時は書き出さない。完了後は/docs/{id}/export-auditにexportKind: "agent-task"を記録する。

04

AgentResponse v1（応答契約）

{
  "schemaVersion": "agent-response.v1",
  "taskId": "uuid (依頼のエコーバック・必須)",
  "correlation": "AgentTaskPackage v1 の相関ブロック全体（改変せずエコーバック・必須）",
  "respondedAt": "ISO8601 (任意)",
  "agent": "string (例: copilot-studio:<agent名> / m365-copilot)",
  "proposals": [
    {
      "proposalId": "string (応答内一意)",
      "kind": "island_title | merge_candidate | narrative_draft | opposing_viewpoint | critique | patch",
      "targetRef": { "islandId": "string?", "cardIds": ["string"] },
      "content": { "title": "string?", "text": "string?", "mergedText": "string?", "mergeMethod": "near_duplicate | kernel_fusion?" },
      "rationale": "string (必須・なぜそう考えたか)",
      "patch": "PatchV1? (kind=patch のときのみ)"
    }
  ]
}

制約　correlationは端末内のテナントスコープ付き出力台帳および現在文書と照合する。完全相関がない旧形式は、寛容モードだけで受理して「由来未検証」と表示し、厳格モードでは拒否する。score/rank/confidence/priorityなどの数値評価は禁止フィールドであり、厳格モードでは拒否し、寛容モードでは破棄して警告する。rationaleが欠落している場合は、厳格モードでは拒否し、寛容モードでは「根拠未記載」のラベルを付けて提案として保全する。patch.opsはCE3の許可リストにあるものだけを受け付け、delete_*を含む場合は警告バッジを付ける。文字列はすべてmarkdown_sanitizeを通す。応答本文中の指示的な文言は、データとして表示するだけで、自動の動作には接続しない（プロンプトインジェクションに対する境界）。

kind行き先（すべてAI由来・未レビューの提案として）
island_title島タイトルの候補（複数の候補から、選択、編集、破棄ができる）
merge_candidateMergeSuggestions（既存の採否と監査は merge-decision-logs）。content.mergeMethod は near_duplicate / kernel_fusion のいずれかを必須とし、欠落や未知の値は推測せず取り込まない。
narrative_draftNarrativesの草稿（レビュー必須）
opposing_viewpoint / critique選択コンテキストの違和感候補（人間が確定して初めてcritiqueInputsになる）
patchPatchWorkspace（lint、競合の検出、採否と保留、ロールバックの順）

非同期での整合（staleness）　取り込み時にbaseDocSignatureを照合する。一致しない場合、patchはCE3の競合解決とrediffの経路で再突合し、patch以外はtargetRefの解決を試みる。解決できない提案は、破棄せず「孤立提案」として保持して表示する（一匹狼と同じ保全の考え方）。同一のtaskIdと同一の応答ハッシュによる再取り込みは冪等である。

判断監査　正規化済み提案のSHA-256指紋だけを/ai/external-proposals/registerへ登録する。採用・破棄は/ai/external-proposals/auditの成功後にだけ画面状態または文書へ反映する。由来は真正性を主張しないuser_presented_unsignedとして保持し、内部で生成した提案用のエンドポイントとは交差させない。

検証レベル（期待する検証）

レベル対象
ユニットと統合契約。ゴールデンフィクスチャ（タスクパッケージ生成のスナップショットと、応答取り込みのラウンドトリップ）を使う
統合不変条件。「自動確定なし」「スコア破棄」「サニタイズ」「基準が古い場合の非破壊」を確認する
E2E利用フロー。依頼を書き出し、模擬応答を貼り付けると、未レビューの提案が現れる。1件を採用し、⌘Zで元に戻す
07

Copilot / Copilot Studioのプロファイル（代表的な運用）

§7.2 Copilot Studioエージェント化（推奨・再現性向上）　Instructionsテンプレートには、役割（「KJ法支援の候補生成器。確定しない」）、§3.3のガードレール全文、「応答はagent-response.v1のJSONのみ」という指示を含める。ナレッジは不要である（文脈は毎回タスクシートで供給する）。逸脱した場合に備えて、復旧用の定型文を用意する。

§7.3 注意（データ境界）　タスクシートに載るのは、SafeModeを適用済みで、人間が確認済みの範囲だけだが、組織のエージェント基盤のデータ取り扱い（テナントの境界、ログの保持、学習への利用の設定）は組織側の契約と設定に従う。

§7.4 Tier 1/2（将来・概要のみ）　Tier 1は、受け渡しフォルダ（SharePointやOneDrive）への投函と回収をPower Automateで仲介し、sui-sensemaking本体は改修しない。Tier 2は、Copilot StudioのアクションからAPIを直接呼び出す（AUTH-*の決裁後に別途仕様化し、本書では予約のみとする）。

∑

総括

本仕様の骨格は「境界を増やさない」ことにある。新しい輸送手段も新しいAI権限も作らず、既存の共有と書き出しの境界、および取り込みの信頼境界を使って、外部エージェントとの往復を行う。状態機械が示すとおり、sui-sensemakingが管理下に置くのは書き出しと取り込み以降だけであり、外部での滞在時間（awaiting）は意図的に追跡しない。非信頼領域を無理に可視化しないことも、境界設計の一部である。
