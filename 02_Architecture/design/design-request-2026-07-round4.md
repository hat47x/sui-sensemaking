# sui-sensemaking デザイン設計要求（Round 4・2026-07-03）

対象: Claude Designセッションへの貼り付け用プロンプト。Round 3（作業モード面ほか）は未回答のため再掲し、今回採択したA/B/Cの実装制約を反映する。

## 貼り付け用プロンプト

追加推奨A（KAカード種別）・B（少数意見の可視化）・C（通し番号＋原データ遡及）のプロトタイプ反映を確認し、プロジェクトとして条件付き採択しました（ADR-0048改訂・issue起票済み: DOMAIN-KA-01 / UX-VISUAL-02 / DOMAIN-TRACE-01）。まず、実装側の制約を3点フィードバックします。以後の設計はこれを前提にしてください。

### A/B/C への実装側フィードバック（制約）

1. **KAカード**: 既存の `Card.text` を「出来事」の正本として維持し、「心の声」「価値」は任意の追加フィールドにします（プロトタイプの選択コンテキスト3欄と同じ形でOK）。カード面（キャンバス）への3欄常時表示はしません。claimType（事実/主張/仮説/不明）とは別軸として扱ってください。
2. **少数意見マーク**: 保持系（amber）と同じ色チャネルを使わないでください（1チャネル1意味の規則）。中立色の淡いマークとし、件数・比率・順位は絶対に表示しない。凡例に「保護対象（無理に分類しない）」の1行を追加。
3. **通し番号・原データ**: 番号バッジのカード面常時表示は既定OFF（初期表示の静けさCB-1）。表示は「表示」パネルのトグルでopt-in。原データ参照は選択時のみ表示。共有時の扱い（出典は内部情報を含み得る→共有前チェックに「出典参照を含める」可否を明示）のUIを設計に含めてください。

### 本題（Round 3 再掲・優先度順）— 未回答のためあらためて依頼します

前提の更新・制約は前回どおりです: 作業モード面の器（`work-mode` 全画面オーバーレイ・Escape閉鎖・フォーカス復帰）は実装済みで中身が空。コンテキストメニュー・ホイールズーム＋LOD・読み順・表札/入れ子島・D&D加入は実装済み。採択済み視覚言語（slate構造/amber=保持系予約/4チャネル/凡例既定OFF）、CB-1〜4自己申告＋5判断軸自己評価、Pending案件（メモ／research⇄businessモード／VUI／レンズヒント）は設計対象外、リアルタイム共同編集は非目標。

1. 作業モード面（領域4）の中身の完全設計
実装済みオーバーレイ内の各タブ — 差分（順序化された確認）／選択マージ（監査ログ・取消）／AI提案（候補・非確定、provider=none時は「AIなしで完結」肯定提示）／診断／文章化（B型） — の完全なレイアウトとフロー。特に:
- 差分: 読込→差分一覧→前提自動選択→適用→取消の全状態（空/読込中/エラー含む）。
- 診断: 反スコアリングの結果表現（点数・ランク・%を使わず「確認が要る箇所」への導線として）。
- 文章化（B型）: 事実=green/解釈=blueの峻別、未解決（保留・違和感）を「保持」として明示。

2. 選択コンテキスト（領域3）の完全設計
「現在の選択」最上部固定の右レール全体仕様。進行中の2フローを含む:
- 違和感→再提案ループ: 違和感付与（5種タグ＋自由記述・理由任意）→制約として再提案（provider=noneでは決定論的候補or肯定的明示）→前回との差分比較→採否（可逆）。
- 根拠・矛盾の人間レビュー: supports/contradictsの確認、矛盾状態（未確認/確認済み/保留/解決済み）の可逆遷移、成果物への含め方。
- 今回採択分の統合: KA 3欄（基本編集群内・未入力時は控えめ）と「#番号・原データ」（選択時のみ）の配置。

3. 共有前確認面（領域5）の詳細設計
「何を誰と共有するか」起点のフロー全体。共有直前サマリ（未レビューn件・違和感m件・矛盾k件は既定で非表示）、公開範囲、レビューパック粒度、取込・復元プレビュー、出典参照を含める可否（今回追加）。SafeMode既定ONの明示性を強化。

4. 段階1実装のレッドライン仕様（実装引き渡し）
カードメタ行＋凡例／空キャンバス誘導について、寸法・余白・タイポ（12/11/10・600/700・2/4/6/8・角丸6/8/999）、状態組合せ代表例（claimType×保留×未レビュー×違和感×矛盾×少数）、凡例の開閉遷移、空状態ヒントの出現・消失条件。

5. アクセシビリティ画面別仕様の完成
今回設計する各面（作業モード面タブ・選択コンテキスト・共有前確認・凡例・一括操作バー）ごとの仕様表: フォーカス初期位置／Tab順／Escape挙動／読み上げ順（型→保持系→確認→根拠→本文）／aria属性。

### 出力形式

面ごとに〔問題〕〔画面設計（状態別）〕〔具体仕様〕〔CB-1〜4自己申告〕〔5判断軸自己評価〕〔移行コスト〕。プロトタイプは依頼1・2の代表フロー（差分適用→取消、違和感→再提案→差分比較、矛盾状態遷移）を操作可能にしてください。
