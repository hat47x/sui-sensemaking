# Claude Design へのデザイン設計要求カバレッジと未要求領域の棚卸し（2026-07-11）

区分: Internal / Informative（次回デザイン要求・照合ラウンドの計画入力）

目的: これまでの設計要求（Round 1〜6）・回答物（`.dc.html` 3点）・実装照合レビュー（第1〜7回）と、実装済みUI面の全量を突き合わせ、設計要求を出していない領域と設計はあるが照合が漏れている領域を分類する。

判定方法と限界: 要求側は `design-request-2026-07-round3〜6.md` の依頼本文、回答側は `.dc.html` 3点のキーワード照合（全文精読ではない）、照合側は `design-qa-checklist.md` の第1〜7回記録に基づく。回答物の該当箇所が薄い可能性がある項目は「部分」と明記した。

## 6. 推奨する次の一手

1. 第8回以降の照合ラウンドでB-1（作業モードタブ内部）を最優先に消化する。回答仕様（拡張提案）が既に存在するため、要求ではなく照合だけで前進できる。QA-MONKEY-11の重なり欠陥が実例として出ており費用対効果が最も高い。
2. A-1（エージェント連携2パネル）は「事後設計照合」としてRound 7相当の要求を1件起こす。Round 6の移行宣言（新規画面設計は原則なし）の例外にあたる新設面のため、実機スクリーンショット＋チェックリスト自己申告を添えて○/△/×レビューを依頼する形が体制と整合する。C-3（「…」マーク）も同じ便で照合に載せる。
3. A-2/A-3（開始パネル・カード検索)はドッグフードの摩擦記録と束ね、次に利用者到達頻度が高い要求候補として保持する。
4. C-1/C-5はADR-0052の決定作業と一体で、デザイン要求として出すか人間のUX Lead判断とするかを先に決める（どちらでも本書の分類は変わらない）。
