# ADR-0083: プロダクト名称と「KJ法」商標の境界を定める

- Status: Accepted（2026-09-11、D1=B・D2=A採択。名称「SUI Sensemaking」、環境変数プレフィックス `SUI_`。C＝弁理士調査はD1の抗弁強化として引き続き推奨するが、改名の実行を待たせない）
- Date: 2026-09-10
- Deciders: Maintainer
- Scope: プロダクト名称、パッケージ名、環境変数プレフィックス、Pythonパッケージ名、文書内識別子（`KJT-*`）、`README.md`, `NOTICE`, `00_Prompt/`, `01_Plans/`, `02_Architecture/`, `03_Implement/`, `04_Documentation/`, CI設定

## Context

### 発端

「OSSであればKJ法の商標は強く問われないのではないか」という前提の妥当性を検討した。
結論として、この前提は本プロジェクトでは成り立ちにくい。

### 商標の事実

「KJ法」は株式会社川喜田研究所の登録商標である（商標登録第4867036号）。
指定区分・現在の権利状態は [J-PlatPat](https://www.j-platpat.inpit.go.jp/) で確認する。

「OSSだから」が抗弁にならない理由は3点ある。

1. 商標法に非営利免責の一般規定はなく、無償配布でも「業として」の使用になり得る。
2. **本リポジトリは既に `saas-multitenant` / `enterprise-production` プロファイル、
   テナント課金・OAuth基盤を実装している。** アーキテクチャが商用SaaSを前提にしている以上、
   非商用を根拠とする主張は現時点で既に弱い。
3. MIT Licenseは著作権のみを許諾し、商標権を許諾しない。名称にリスクがあるなら、
   それを全ダウンストリーム利用者へ伝播させていることになる。

### 3つの法域は別々に振る舞う

| 法域 | 対象 | 文書量を増やしたときの挙動 |
|---|---|---|
| **商標権** | 名称の出所表示的使用 | **ほぼ横ばい**。方法論の説明・言及は商標法26条の記述的使用に当たり、原則として権利範囲外 |
| **著作権** | 川喜田二郎の著作の表現・図表・例題 | **増加する**。原典の構成・語彙・例題を忠実になぞるほど翻案と評価される余地が増える。保護は2079年末まで |
| **不正競争防止法** | 出所混同・信用毀損 | 未検証のツールが著名方法論名を冠する構図は、権利者の懸念動機になり得る |

ゆえに「深く文書化すること」で変わるのは、商標リスクではなく著作権リスクである。
一方、名称は文書量と無関係に商標リスクを負い続ける。

### 実測した露出（2026-09-10）

| 層 | 実測 | 商標リスク | 変更コスト |
|---|---|---|---|
| UI文字列（i18n ja/en） | **0件** | なし | 該当なし |
| 文書中の「KJ法」言及 | 約40件 | ほぼゼロ（記述的使用） | 低 |
| ファイル名（`kj_technique.md` 等） | 数十件 | 低 | 中 |
| パッケージ名（`kj-atlas-frontend` / `-backend`） | 2件 | 高 | 中 |
| 環境変数 `KJ_ATLAS_*`（旧） | **2,230件 / 389ファイル** | 中〜低（設定キーは出所表示性が弱い） | **極大**（公開設定契約） |
| プロダクト名 `kj-atlas`（旧） | リポジトリ / README / 将来のドメイン | **最高** | 高（プレリリースの現時点なら実行可能） |

利用者は製品UI上で一度も「KJ法」を見ない。露出は名称と識別子に集中しており、
利用者体験には及んでいない。これは想定より良い位置である。

### なぜ今決めるか

訴訟に至る確率は低いと見る。この種の権利者はまず警告書を送るのが通例であり、
主たる標的は商用研修・認定事業である。この判断が必要になる理由は、訴訟確率ではなく非対称性にある。

- 今（プレリリース、外部利用者の検証未実施＝`ADR-0042` 段階A）に改名するコスト: 低
- 公開・商用化後に改名するコスト: ドメイン・パッケージ名・認知の全損

放置するほど、この非対称性は一方向に悪化する。

## Decision

### D1: プロダクト名称

| 案 | 内容 | 評価 |
|---|---|---|
| A | `kj-atlas` を維持し、`NOTICE` の帰属表示だけで対応する | コストゼロ。ただし最大の露出（名称）が残り、商用化・ドメイン取得の時点で判断を再度迫られる |
| **B（推奨）** | 易経由来の別名へ改名し、KJ法は出典言及に限定する | 商標露出を名称から除去。プレリリースの現時点なら実行コストが最も低い |
| C | 弁理士の商標調査（指定区分の確認を含む）を経てから判断する | 最も確実。B と排他ではなく、**B の実行前に併走させるべき** |

決定（2026-09-11）: Bを採択。名称は「SUI Sensemaking」。C（弁理士調査）はD1の抗弁を
強化する目的で引き続き推奨するが、プレリリース期という一度きりの安価な改名機会を逃さないため、
改名の実行を待たせない。指定区分（第9類・第42類）の確認は改名後でも行える。

#### 採択名称: SUI Sensemaking

- **SUI**は、易経第45卦「澤地萃」に由来する。「群れ集まる／集めて一つにする」の意である。
  散在する断片が群れをなすという、本製品の動作そのものを指す。
  `SOZA(綜座)` / `TEI(鼎)` / `SUI(萃)` として易経由来の命名系列が揃う。
- **Sensemaking**は、カテゴリを示す中立・非商標の英語一般名である。
  HCI・組織論・情報分析・デザインリサーチの各分野で確立した語であり、
  「曖昧・断片的な情報から意味を立ち上げる」という本製品の目的をそのまま指す。
  「KJ法」という商標語をカテゴリ名から外し、代わりにこの語を用いる。

#### 採択名称の背景（要旨）

本プロダクト群は易経由来の命名系列を持つ（`TEI(鼎)` = 第50卦）。
これに対し、萃 = 第45卦「澤地萃」を提案する。三つの層で整合する。

1. **易経整合**: 萃は「群れ集まる／集めて一つにする」の意である。散在する断片が群れをなすという、
   本製品の動作そのものである。`SOZA(綜座)` / `TEI(鼎)` / `SUI(萃)` として系列が揃う。
2. **機能一致**: 親和図法の本質はaffinity（寄り集まり）である。萃はその日本語圏における最古層の語である。
3. **知的系譜**: 南方熊楠の「萃点（すいてん）」は、南方曼陀羅において諸理が交わる一点であり、
   そこを掴むことで背後の理へ速く到達しうるとされた概念である。
   本製品の「断片統合」「空白探索」という目的とほぼ同義である。
   南方熊楠は1941年没であり、著作権は保護期間満了済み（パブリックドメイン）。萃点は商標でもない。

この選択はKJ法を捨てるものではない。**KJ法自身がその中に位置する、より古く、
かつ権利的に自由な日本の知的系譜へ立ち返る**ものである。
川喜田二郎への敬意は `NOTICE` と各文書の出典表記で明示的に維持する。

#### 実行範囲の確定

- `kj_technique.md` / `ai_kj_execution_procedures.md` はファイル名を変更する
  （`sensemaking_technique.md` / `ai_sensemaking_execution_procedures.md`）。
  被参照が多いため、`AGENTS.md`・全issue・全ADRの参照を同一PRで更新する。
- 過去ADRのファイル名スラグ（例: `ADR-0048-...-kj-vocabulary.md`）は変更しない。
  歴史記録であり、`DC-LNK-002` の引用検査に無用な影響を与える。ADRの本文は語彙移行に追随する。
- **`01_Plans/dogfood/doc_kj_atlas_dogfood_r*.json`**（43件、KJキャンバス分析スナップショット）は
  ファイル名を `doc_sui_sensemaking_dogfood_r*.json` へ改称するが、中身は1バイトも変えない
  （`git mv` のみ）。blobのハッシュ値は内容の関数であり不変、凍結整合性は保たれる。
  同ファイル群を参照する検証器（`validate_dogfood_docs.py` のglob / 正規表現）と
  約30の `.md` 参照も同一PRで追随させた。
  凍結ソースマニフェスト（`cognitive-dogfood-case-00*-round1-source-manifest.json`）は
  凍結コミット時点のパスを保持するため改称しない（同manifestの
  `commonSources` パス検査は現在ツリーではなく凍結コミットに対して行われる）。

### D2: 環境変数プレフィックス（実測: `git grep` で 389 ファイル・2,230 出現）

| 案 | 内容 | 評価 |
|---|---|---|
| **A（採択）** | `KJ_ATLAS_` → `SUI_` へ一括改名（互換なし） | プレリリースかつ外部利用者の検証未実施のため、移行対象となる既存デプロイが存在しない。総コスト最小。利用者からの明示指示「SUI始まりで短く」に一致 |
| B | 両読み対応（旧キーも読み、警告を出し、N版後に削除） | 最も安全だが、存在しない利用者のために恒久的な複雑性を負う（`ADR-0039` の物量抑制に反する） |
| C | D1 に従属させる（起票時の案） | D1 = B が確定したため、この従属条件は解消した。A を実行する |

決定（2026-09-11）: Aを採択。新プレフィックスは `SUI_`（`SUI_ATLAS_` ではない）。`ATLAS` も旧名の一部であり残す理由がない。
`runtime_parameter_registry.md` を同一PRで全面同期する。

### D3: 文書の一次語彙（本ADR起票と同時に実施済み）

中立な一般名称である親和図法（affinity diagram）とsensemakingを一次語彙とし、
「KJ法」は出典を示す説明的言及に限定する。既に以下を実施した。

- `NOTICE` を新設し、商標帰属・非公認・出典・著作権保護期間を明示
- `README.md` の自己記述を「KJ法インスパイア型」→「親和図法系」へ変更し、
  川喜田二郎からの影響を明記したうえで非公認である旨を併記
- `README.md` にライセンスと商標の節を追加し、MITが商標を許諾しないことを明示

## 非目標

- KJ法への言及そのものを削除すること。出典の秘匿は敬意に反し、かつ記述的使用は適法である。
  目的は出所表示的使用の除去であって、系譜の否認ではない。
- 環境変数の単独改名（D2 = CのとおりD1に従属させる）。
- i18n / UI文字列の変更。実測0件であり対象が存在しない。
- 凍結記録の中身の書き換え（`doc_*_dogfood_r*.json` の分析テキスト、
  `cognitive-dogfood-case-00*-round1-source-manifest.json`、
  `hat47x/kj-atlas@<commit>` 形式の凍結スナップショット参照）。
  これらは過去の状態を記録するもので、当時のリポジトリ名は `kj-atlas` であった。
  スナップショット参照・manifest・凍結検証器の定数（`FROZEN_PRODUCT_REPOSITORY` 等）は
  `hat47x/kj-atlas` のまま残す。
- 過去issue（`01_Plans/issues/done/`）のファイル名スラグの遡及改名。
- 川喜田二郎の著作からの引用・図表転載の追加。著作権保護期間中である。

## Consequences

### 期待される効果

- 最大の商標露出（名称）が除去され、商用SaaS化・ドメイン取得の判断が名称問題から解放される。
- MITライセンス下のダウンストリーム利用者へ商標リスクを伝播させなくなる。
- 易経由来の命名系列（`SOZA` / `TEI` / `SUI`）が揃い、プロダクト群としての一貫性が生まれる。
- 「萃点」という実装可能なドメイン概念を新たに獲得する。

### 想定される副作用・制約

- 改名はリポジトリ名・パッケージ名・環境変数・CI設定・デプロイ設定へ広く波及する（D2 = Aの場合、1,966箇所）。
- 既存の外部リンク・ブックマーク・GitHub starはリポジトリ名変更のリダイレクトに依存する。
- 「kj-atlas」で既に認知が発生している範囲では、周知コストが発生する。
- 著作権リスク（`00_Prompt/` の記述が原典をどれだけ忠実になぞっているか）は本ADRでは解消しない。
  別途、記述姿勢の監査が要る（下記）。

### 移行時に必要な対応

1. D1の採択（保守者判断）。C（弁理士調査）を併走させる場合は、指定区分に第9類・第42類が
   含まれるかを最優先で確認する。この一点でリスクの性格が大きく変わる。
2. D1 = Bの場合、D2 = Aを実行し、`02_Architecture/runtime_parameter_registry.md` と
   全デプロイ設定を同期する。
3. `00_Prompt/` の著作権監査。`kj_technique.md` は本ADR起票時に一次対応済み
   （後述「起票時に実施した是正」）。残る `ai_kj_execution_procedures.md` 等についても、
   原典の構成・用語・例題を忠実になぞっていないかを確認し、
   「KJ法の手順」ではなく「本ツールの手順（KJ法に着想）」として再記述する。
4. `AGENTS.md` の語彙移行。同書は全AIセッションの入口であり、
   §1.2「操作別モデルレベル」表の見出しが「KJ操作」、§2最小読取ルール表の行名が
   「KJ法の概念」「KJ法の実行」となっている。ここを中立語彙へ移すと、
   以後の全セッションへ正しい語彙が伝播する（波及効果が最も大きい一箇所）。
   ただし同書は並行セッションが常時参照するため、D1確定後に一度で行う。
5. `KJT-*` 識別子（46箇所）の扱い。`DOC-NORM-01` により識別子参照が義務づけられた
   安定契約であるため、環境変数と同様、D1の従属変数として扱う（単独改名しない）。
6. `NOTICE` の「4. 本プロジェクト自身の名称について」節を、決定内容で更新する。

### 起票時に実施した是正（D3 の一部）

`00_Prompt/sensemaking_technique.md`（旧 `kj_technique.md`）の題名が
`渾沌をして語らしめる` であり、
これは川喜田二郎の著書『KJ法—渾沌をして語らしめる』（1986, 中央公論社）の書名そのものであった。
書名は一般に著作物性を欠くため直接の著作権侵害には当たりにくいが、
「KJ法を再構成した」という自己記述と組み合わさることで、
本書が原典そのものであるかのような出所の印象を生む。これを是正した。

- 題名: `渾沌をして語らしめる — 情報の統合的整理` → `統合的整理の手順 — 断片から全体像を立ち上げる`
- 自己記述: 「川喜田二郎のKJ法を、生成AIが実行するための形に再構成した」→
  着想元であること・本プロジェクトが独自に構成した手順であること・公認実装ではないことを明記し、
  あわせて欠けていた書誌情報（『発想法』1967／『KJ法』1986）を補った

なお本書が中核概念として用いる「渾沌」は荘子の寓話に由来し（本文§で明示済み）、
古典としてパブリックドメインである。概念の実質は保持し、書名の借用のみを解消した。

## Three-Element Verification（ADR-0067）

| 次元 | このADRでの主張 | 他次元への制約 |
|------|----------------|---------------|
| **業務設計** | 権利者から公認されていない以上、製品は「KJ法の実装」を名乗らない。同時に、着想の出典を秘匿することは敬意に反するため、記述的言及としては明示し続ける。名乗り（出所表示）と出典表示（帰属）を分離する | データ: 文書の一次語彙は中立名（親和図法）とし、KJ法は出典欄へ移す。機能: UI文字列には方法論名を出さない（現状0件を維持する） |
| **データ設計** | 商標・出典・帰属の正本を `NOTICE` に単一化し、`LICENSE`（著作権）と役割を分ける。川喜田二郎の著作は保護期間中、南方熊楠の著作は満了済みという差を記録する | 業務: フォークや再配布時の判断材料を利用者へ渡せる。機能: README からリンクし、利用者が最初の導線で到達できる |
| **機能設計** | 名称は識別子としてリポジトリ / パッケージ / 環境変数の3層へ波及する。環境変数は名称決定の従属変数とし、独立改名しない。凍結済み履歴成果物のファイル名は遡及改名しない | 業務: プレリリース期という一度きりの安価な改名機会を使う判断を保守者へ返す。データ: `runtime_parameter_registry.md` が環境変数の正本であり、改名時は同一PRで同期する |
