# ADR-0089: プロダクト価値の正本と、価値をADRへ反映する規則

- Status: Accepted
- Date: 2026-10-01
- Deciders: Maintainer
- Scope: `01_Plans/adr/`, `ROADMAP.md`, `README.md`
- Supersedes: 価値の「現在の定義」に関する `ADR-0001`・`ADR-0011`・`ADR-0036`・`ADR-0037`・`ADR-0038`・`ADR-0042` の運用部分（原則・不変条件・モデルそのものは `ADR-0010`・`ADR-0032`・`ADR-0041` が引き続き正本）

## Context

プロダクト価値がADR-0001/0010/0011/0032/0036/0037/0038/0041/0042などへ分散し、一次利用仕事と切替理由は削除済みのissue（`PRODUCT-POSITION-01`）にしか書かれていなかった。管理文書の整理（2026-10-01）でissue台帳を廃止したため、価値の現在地を1か所で読める正本が必要になった。あわせて、ADRが価値へどう寄与するかを毎回確認する規則がなく、運用系のADR（フェーズ計画、文書運用、認証的なガバナンス）が価値判断と混ざっていた。

開発体制は **1人の開発者＋生成AI** である。外部協力者や複数人承認を前提にした検証・統治は置かない。

## Decision

### 1. 一次利用仕事

> まとまりきらない定性資料や観察を、早すぎる分類・要約・合意で潰さず、出典・異論・保留・人間の判断権を残したまま構造化し、後から根拠へ戻れる共有可能な理解へ育てる。

### 2. 切替理由

次の痛みが重なり、既存手段の運用上の工夫と乗り換えコストを上回ったときに選ばれる。1項目だけで乗り換えるとは想定しない。各項目は、当てはまる利用者と当てはまらない利用者を併記する（T3、`provisional`）。

- 付箋/ホワイトボード: なぜその束・結論になったかを後から根拠へ戻りにくい。（付箋を使う調査者には通じる。リンクや手書きIDで一部は埋められ、単独では乗り換えの決め手にならない）
- 一般的なAI要約/クラスタリング: 少数意見・違和感・保留が、きれいな結論へ吸収されやすい。（AI要約を日常的に使う人が実感する。使わない人には「警戒の理由」として通じる）
- 質的分析ツール: コード体系や分析者の枠を先に強く持ち込みたくない探索初期に合わない。（T3では支持されなかった。コード先行の手法を欠点扱いしない。実在者での確認まで保留）
- 文書/スプレッドシート: 距離・配置・関係・空白を使った構造発見が弱い。（紙や付箋で構造を扱う人にだけ当たる）
- クラウド前提の共同ツール: 機微な定性資料を local-first / offline で扱いにくい。（痛みは強いが、外部送信なしで動くことを利用者が文書で確認できることが前提。未確認の主張はしない）

### 3. 競わない軸

最速の自動要約、自動での正解・合意・意思決定、汎用ホワイトボードの機能数、定量・統計解析、人間のレビューを省くAIエージェント化。

**適合範囲**: 既存の道具との併用が前提で、置き換えは想定しない。速さと件数が中心の仕事（集計、短納期の要約）、「何人が言ったか」を出す仕事、当日の場づくりを紙で行う場面、コード体系を先に決める手法の置き換えには合わない。この範囲外の利用者が使わないと判断することは、改善要望に変換せず適合範囲の限定として扱う。

### 4. 価値の構成（既存ADRへの索引）

| 層 | 内容 | 正本 |

| 価値原則 P-01〜P-09 | 意味の保留、反スコアリング、人間レビューの追跡、HITL反復、カード数の可管理性、視点制御、self-host/privacy、定性情報への忠実性、累積的探究 | `ADR-0010`（詳細は `ADR-0001` §1） |

| 累積的探究 | W型反復 | `ADR-0057` |

### 5. 価値仮説と現在の証拠状態

価値の実在は、証拠階層を付けて記録する。階層はT1（実在の第三者の実資料）、T2（Maintainer自身の、SUI自身を題材にしない実務利用）、T3（生成AIが演じる参加者）。T1は必須ではない（外部協力者の確保を完了条件にしない）。T3のみに基づく判定は `provisional` と書く。SUI自身を題材にした内部dogfoodは、いずれの階層にも数えない。

| 仮説 | 内容 | 現在の証拠 |
|---|---|---|
| H1 | 一次利用仕事と切替理由が、実在の仕事に対応する | **narrow**（T3、`provisional`、2026-10-02）。後半の核（出典・異論・保留を残し、後から根拠へ戻れる）に絞る。付箋づくり、集計・件数、匿名化・同意範囲は一次利用仕事の外。切替理由は項目ごとに当てはまる人が分かれた |
| H2 | 人間が残した根拠・異論・保留・関係をAI支援の途中でも落とさない（意味の保全） | 実装済み（LLM入力IR、`ADR-0069`）。`check-narrative` のscale方式が未決（入力約14万token、無料枠モデルでの参考値） |
| H3 | 初回の10分で、近さと保留を自分で判断する体験が得られる | **modify**（T3、`provisional`、机上確認）。「説明できる」までは言えるが、教程が答えを先に与えており、自分の判断とは言えない。観測項目に (a) 教程の答えを伏せても同じ説明ができるか、(b) 判断理由が画面上に残るか、(c) 強い価値の瞬間の有無、を加える（c は未確認） |
| H4 | READMEの冒頭が、一次利用仕事を初見者に伝える | **narrow**（T3、`provisional`）。方向性と誠実さは伝わるが、入力・出力・始め方が伝わらない（提示範囲の制約の可能性あり）。README冒頭へ具体例を追加済み |

#### T3パイロット（2026-10-02）の記録

- 参加者: AIが演じた5名（UXリサーチャー、デザインリサーチャー、懐疑的な企画担当、自治体の住民参加ファシリテーター、臨床質的研究者。後者2名は異なる実践文化）。演じたモデルは Codex GPT-6 Astra ではなく、本セッションのClaude。
- 手順: 現状把握（製品情報なし）→ README冒頭 → 一次利用仕事の提示 → 初回サンプルの机上確認 → 利用判断。ステージごとに文脈を分離し、分析後に3つの反証レンズ（模擬特有の歪み、反証の保持、過大判定）で検証した。
- 結果: 「使う」と答えた参加者は0人。条件付き3名、実質不採用2名（自治体は当日の場を紙のままにする、臨床は既存ツールを置き換えない）。強い価値の瞬間を述べた参加者は0人。READMEの開発中警告は全員が「本番利用には時期尚早」と受け取った。
- 限界: 全員が似た構成で答え、一致は提示語彙への同調や迎合の可能性があるため根拠に使わない。数値（枚数・日数）と文化的摩擦は設定からの生成で、実在者での確認が必要。教程は机上確認のみ。
- 反映済み（2026-10-03）: getting_started を、先に自分の見立てと理由を書き、答えを事後の例へ回す構成へ変更（理由の記録先は手元メモ。画面上の記録欄は未確認）。未実施（実画面または実在者での確認後）: 保存・再読込・共有前確認の分離、用語（「未決」→「保留」）の見直し。

公開文書で価値の実証を主張するときは階層を明記する。T3のみを根拠に「第三者が確認した」と書かない。

### 6. 機能・設計判断の優先順位判定

新しい機能案や構造改善は、一次価値への寄与を次の3つに分けて評価し、直接性と代替経路の有無で優先度を決める。

1. **意味の保全**: 根拠・異論・保留・関係を落とさない。中核価値に直結する。
2. **運搬の便利さ**: 外部AIとのやり取りなどを短くする。手動の代替があれば後回しにする。
3. **構造の整頓**: 内部の共通化や整理。通常経路が動いている限り急がない。

### 7. ADRへの反映規則

- 新規ADRは冒頭に **「価値への寄与」** を1〜3行で書く。対象は価値ループ（V0〜V4）、価値原則（P-xx）、不変条件（CVI-x）、または「安全 / 保守 / 運用のみ（価値への寄与なし）」のいずれか。
- 「価値への寄与なし」のADRは、一次価値を損なわないことだけを確認して起票する。優先度は §6の3分類で判定する。
- 不変条件（CVI）を緩める提案は、本ADR・`ADR-0041` を更新するADRでのみ行える。
- 価値の定義（§1〜§3）を変える場合は、本ADRを改訂し、変更理由とどの証拠階層に基づくかを書く。
- ADRテンプレートを上記に合わせて更新する。三要素整合表・測定器整合欄は必須としない。

### 8. 運用系ADRの整理

次のADRは、現在の体制（1人＋生成AI）では運用上の力を持たないため `Superseded` とする（本文は履歴として残す）。

- フェーズ計画・バックログ: `ADR-0002`〜`ADR-0007`、`ADR-0012`
- 文書運用ゲート: `ADR-0022`〜`ADR-0025`
- 多エージェント運用・ブランチ統治: `ADR-0034`、`ADR-0045`
- 設計方法論と自律性レベル: `ADR-0047`、`ADR-0067`、`ADR-0075`

`ADR-0039`（個人OSS・プレリリースのガバナンス）は有効のまま、本ADRの §5に沿って証拠階層を使う。`ADR-0037` の二軸スコアカードは、統治軸（CVIの非後退）だけを維持し、集計・Go/No-Goの運用は行わない。

## Consequences

- 価値の現在地と一次利用仕事を、`ROADMAP.md` と本ADRで読める。
- 新規ADRが価値へどう寄与するか、または寄与しないかが明示される。
- 価値の実在（H1）が未検証であることが、記録として残る。強い主張を避ける根拠になる。
