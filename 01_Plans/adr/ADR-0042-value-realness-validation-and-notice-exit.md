# ADR-0042: 価値実在の検証と NOTICE 脱却基準

- Status: Accepted
- Date: 2026-06-10
- Deciders: Maintainer（委譲された意思決定権限）
- Scope: `01_Plans/`, `README.md`

## Context

`README.md` は冒頭で明示している。

> 本ツールは生成AIを用いた開発中であり、現時点では人的レビュー・利用を伴っていないことをここに明示します。

機能は出揃いつつある（CE0–CE4 Done、DOMAIN-EXPR/PRODUCT-VALUE進行、undo/redo・LLM provider実装済み）。だが**作られた価値が実在するか、つまり、実際に人が使って「曖昧さを保留したまま思考が前に進んだ」と言えるかは、誰も検証していない**。

`ADR-0036`（価値→社会的目標）と `ADR-0037`（観測ハーネス）は観測の枠組みを定義したが、`ADR-0039` によりVR4/VR5としてactivationは延期されている。その結果、現段階には「価値が実在することをどう確かめ、いつNOTICEを外すか」の**判定基準が空白**になっている。

価値最大化の観点では、これは2番目に大きい欠落である。実装をいくら積んでも、価値が届いているかの確認経路がなければ、次に何を直すべきかも分からない（改善のフィードバックループが閉じない）。

個人OSS・プレリリース段階（`ADR-0039`）では、重量級のKPI観測やユーザー調査は過剰である。必要なのは**最小の、実行可能な自己検証（ドッグフード）と、その結果でNOTICEを段階的に外す基準**である。

## Decision

価値実在を最小コストで検証する「ドッグフード経路」と、その結果に基づくNOTICE脱却基準を定義する。

### ドッグフード最小経路（Maintainer 自身が実施）

実ユーザー獲得を待たず、Maintainerが自分の実題材（実際に迷っている論点・未整理のメモ）で次を1回通す。

1. 空状態または自分のメモから開始し、カードを置く。
2. 少なくとも1つの保留（Hold）・違和感（Critique）・根拠不足を「失敗ではなく作業状態」として残す。
3. まとまり／関係を作り、俯瞰⇄詳細を往復する（必要ならundoで配置をやり直す）。
4. 共有前確認を通し、確定点・保留点・未レビュー情報・根拠への戻り方を含む成果物を1つ出す。
5. その過程で「思考が雑にならなかったか」「早すぎる収束を強いられなかったか」を所感として記録する。

### 検証の記録（軽量・文書のみ）

- 結果は `01_Plans/` 配下の単一メモ（`dogfood-log-<date>.md`）に、所感と発見した摩擦点（friction）を箇条書きで残す。重量級のテンプレ・スコアカードは課さない。
- 摩擦点は、根幹価値を損なうもの（例：保留が削除に見える）を優先度高としてissue化する。価値を損なわない使い勝手は低優先で記録のみ。

### NOTICE 脱却の段階基準

`README.md` のNOTICEを次の段階で書き換える（削除ではなく段階表現へ）。

- **段階A（現状）**: 「人的レビュー・利用を伴っていない」。
- **段階B（ドッグフード済）**: Maintainer自身の実題材で上記経路を1回以上完走し、根幹価値を損なう摩擦点が解消済み。NOTICEを「メンテナ自身による試用は行ったが、第三者の継続利用は未検証」に更新してよい。
- **段階C（第三者利用）**: 外部協力者または実ユーザーが1名以上、自分の題材で価値到達を報告。NOTICEを一般的な「開発中」表現に緩和してよい（`ADR-0039` の再導入トリガーと同期）。

判定はMaintainer単独で確定してよい（`ADR-0039` のsolo段階適正化に準拠）。

### 非目標

- 行動ログ・テレメトリ・個人追跡の導入（`ADR-0036` 非監視制約を維持）。
- 定量KPIの活性化（VR4として延期中。本ADRは定性の自己検証に限定）。
- 公開リリースやマーケティングの計画。

## Consequences

- 期待される効果
  - 「価値が実在するか」の確認経路ができ、改善フィードバックループが閉じる。
  - NOTICEの更新条件が明確になり、段階を恣意でなく事実で進められる。
  - 摩擦点がissue化され、次に直すべきものが価値起点で決まる。
- 想定される副作用と制約
  - ドッグフードはMaintainerの時間を要する（ただし1経路・定性で最小化）。
  - 自己検証にはバイアスが含まれる。段階C（第三者）まではNOTICEを完全には外さない設計で、これを和らげる。
- 移行時に必要な対応
  - 実施時に `01_Plans/dogfood-log-<date>.md` を作成する。
  - 摩擦点issueは既存backlog（PRODUCT-VALUE / DOMAIN-EXPR）へ紐付ける。
