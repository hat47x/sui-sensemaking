# ADR-0098: 人による入力の自己申告と、SafeMode共有境界での島の題名・要約の扱い

- Status: Accepted
- Date: 2026-10-20
- Deciders: Maintainer
- Scope: `03_Implement/frontend/src/App.tsx`（`handleIslandTitleChange`、`handleIslandSummaryTextChange`）、`03_Implement/frontend/src/ui/SidePanel.tsx`、`03_Implement/frontend/src/export/context_bundle_projection.ts`、`02_Architecture/api.md`、`03_Implement/mcp/README.md`、`04_Documentation/getting_started.md`
- Related: `ADR-0041`（CVI）、`ADR-0068`（SafeModeのAPI境界）、`ADR-0089`（価値の正本）、`ADR-0093`（agent向け投影）、`ADR-0096`（読み取りAPIのSafeMode投影）

## 価値への寄与

V3「レビュー」とCVI「`human_reviewed` は人間だけが設定する」に寄与する。人が書いた題名・要約を、追加の確認操作なしに人間の判断として記録できるようにしつつ、AI生成文を人間の確認済みへ昇格させない。共有境界は広げない。

## Context

島の題名と要約には、それぞれ `titleReviewed` と `summaryReviewed` がある。現行実装では、人が題名や要約を編集すると、その時点でレビュー済みとして記録する（`App.tsx` の `handleIslandTitleChange`、`handleIslandSummaryTextChange`）。また、AIが生成した題名・要約は未レビューとして保存し、人が確認したときだけレビュー済みになる。

Issue #3230 は、手入力の要約をレビュー済みとみなすことが `human_reviewed` の意味と食い違わないかを問うた。Issue #3229 は、レビュー済みの島の題名が未レビューのカード本文を引用し得るため、SafeModeがONのとき題名も墨消しするかを問うた。

現行の外部経路は一様ではない。

- agent向けの読み取り投影（`context_bundle_projection.ts`）は、`titleReviewed === true` の題名をSafeModeがONでも返し、未レビューの題名は `(未レビュー)` に置き換える（ADR-0093）。
- 共有・書き出し用の投影（`inquiry_bundle_safe_mode.ts`）は、島の題名をSafeModeで常に墨消しする。
- アプリ内表示は、人が確認する作業のために未レビュー本文も表示する。

この差は経路ごとの役割の差であり、同じ規則に揃える必要はない。一方で、どちらの経路でも「人が確認した題名」をどう扱うかは決めておく必要がある。

## Decision

### 1. 人による編集は人間の自己申告として扱う

人が島の題名または要約を編集した場合、その内容は人間が作成した判断として扱い、`titleReviewed` / `summaryReviewed` を `true` にする。追加の「確認しました」操作を必須にしない。

理由は次のとおりである。

- 人が自分で書いた文を、書いた本人に再確認させる操作は、意味の追加がないままレビュー動線を重くする。
- `human_reviewed` が禁じているのは、AIや自動処理が人間の確認を偽装することである。人が書いた文を人間の入力として記録することは、この禁止に当たらない。
- レビュー済みの印を取り消すチェックボックスは既にあり、内容を確認せず共有したくない場合は人が明示的に外せる。

AIが生成した題名・要約は、従来どおり未レビューで保存する。AI出力を人間の確認済みへ自動昇格させない。

### 2. SafeModeは、レビュー済みの短い見出しを再検査しない

SafeModeがONでも、agent向けの読み取り投影は `titleReviewed === true` の島の題名を返す。未レビューの題名は返さない。

題名は、外部の読み取りで島を識別するための短い見出しであり、人が確認した案内標識である。これをSafeModeで一律に消すと、既定ONのSafeModeの下でagentが島を識別できなくなり、ADR-0093が認めた読み取りの価値を失う。空隙の題名を墨消しするのは、空隙の題名が未レビューの本文を含み得るうえ、人が確認したという印を持たないためである。同じ扱いにはしない。

共有・書き出し用の投影が題名を墨消しする現行方針は変更しない。経路ごとの役割の差を、このADRで一様な規則へ揃えない。

### 3. 残る危険を明示する

レビュー済みの題名や要約が、未レビューのカード本文を引用している可能性は残る。この危険は、内容を機械的に走査して消すのではなく、次の二点で扱う。

- 題名・要約をレビュー済みにする操作が、外部へ出る範囲を広げることを文書に明記する。
- 未レビューのカード本文を題名・要約へ引用する必要がある場合は、人がレビュー済みの印を外すか、引用を避ける。

見出しの文字列と未レビュー本文の部分一致を検査するような自動判定は採らない。言い換え・要約・表記揺れで容易に外れ、誤検知で正当な見出しを止めるためである。

### 4. 対象外

- `human_reviewed` の意味を、内容の真偽の保証へ広げない。
- レビュー済みの題名を、共有・書き出しで無条件に出すよう変更しない。
- 未レビュー本文のローカル表示、AI入力の拒否、共有・書き出しの拒否を変更しない。
- 本文の内容をAIで審査して、レビュー状態を自動で決めない。

## Consequences

- 人が題名・要約を書く通常の操作は、従来どおり一度で完了する。
- agentは、SafeModeがONでもレビュー済みの島の題名で構造を辿れる。未レビューの題名は引き続き見えない。
- レビュー済みの短い見出しが未レビュー本文を引用する危険は、人の確認責任として残る。この危険を消したとは主張しない。
- 共有・書き出しとagent読み取りの投影は、引き続き別々の規則を持つ。将来統一する場合は、別のADRで決める。
