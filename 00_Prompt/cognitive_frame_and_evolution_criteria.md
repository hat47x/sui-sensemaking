# sensemaking基盤としての SUI Sensemaking — 存在理由と進化の判断基準

- Status: Normative
- Updated: 2026-08-15
- 根拠: `01_Plans/research/product-trajectory-research-2026-08-15.md`
- 関係: `domain.md`（不変条件の正本）、`ai_cognitive_externalization_requirements.md`（本書は同書 §1.1 の正当化を差し替える）

本書は、**この製品が何のために存在し、変化する環境の中で何を変えてよく何を変えてはならないか**を定める。個別の設計判断は行わない。判断の基準を定める。

---

## 1. 存在理由

> **SUI Sensemaking は、人間と人工認知系が未整理な材料から意味を形成し、その過程を蓄積・再検証できるsensemaking基盤である。**

分解する。

- **KJ法に着想を得たキャンバスは、中核的な人間系sensemaking interfaceである。** 未分化な情報から意味を立ち上げ、早すぎる収束を避けるための重要な認知フレームとして扱う。
- **SUI Coreは特定の一手法に閉じない。** AI固有の探索、複数認知系の比較、将来の新しいsensemaking protocolも、Evidence・関係・仮説・構造・来歴を失わない限り受け入れられる。
- **認知拡張は、認知主体が誰であっても成立する。** 人間にも、AIにも、両者の協働にも適用でき、役割分担は固定しない。
- **本製品はその蓄積基盤である。** カードや島だけでなく、観察、関係、仮説、構造、統合、保留、違和感、来歴を跨セッションで保持し、後から辿り直せる状態を目指す。

### 1.1 この定義が満たすべき条件

**sensemakingを外在化し、その形成過程を蓄積するという枠組みは、AIがどれだけ発展しても成立する。** 能力の高い認知主体ほど、より広い探索や統合を担えるため、AI能力の向上はSUIが支えられる委任区間を広げる。したがって**AI能力の向上は本製品にとって追い風である。**

### 1.2 禁じられた正当化

次の形式で製品を正当化してはならない。

> ❌ 「生成AIには〜ができない。だから外部の足場が要る」

これは**欠損ベースの正当化**であり、論理形式は「AがXできない → だからBが要る」である。**AがXできるようになれば正当化は消える。** 実際、かつて列挙された限界（文脈の長期保持、前提関係の維持、事実と仮説の峻別）は既に縮小している。

欠損ベースに立つと、AI能力が上がるたびに「AIにはできない領域」を探すことになり、その探索は**必然的により狭い領域へ後退する。**

**正しい形式は次である。**

> ✅ 「sensemakingの過程を外在化し、根拠・保留・対立・来歴とともに蓄積することは、認知主体が誰であれ認知を拡張する。KJ法に着想を得たキャンバスは、その中核的な人間系インターフェースの一つである」

## 2. 不変条件は、推論の質の要件である

`domain.md` が定める不変条件は、**人間を守るための制約ではない。推論の質を保つための構造である。** 倫理的要請と工学的要請はここで一致する。

各不変条件は、次の理由によって成立する。**「AIが信頼できないから」という理由を用いてはならない。**

| 不変条件 | **成立理由（推論一般の要件として）** |
|---|---|
| **保留** | 早すぎる収束は推論の質を下げる。問いが開いているなら、答え手が誰であれ開いたままにするのが正しい。保留は未完了ではなく、**探索空間を閉じない操作**である |
| **違和感（説明責任を伴わない）** | 根拠を言語化できない差異は、**圧縮前の信号**である。根拠の提示を要求することは、圧縮できた信号だけを残すフィルタであり、情報損失を生む |
| **可逆性** | 確定は探索の停止である。任意の推論者にとって、探索空間を不可逆に閉じてはならない |
| **生成主体と承認主体を混同しない** | AIは作業空間の中で観察・仮説・構造・統合を自律生成してよい。ただし、それを人間が理解・承認した意味や共有済みの正規状態へ自動的に読み替えてはならない。**生成と権限昇格は別操作**である |
| **共有物に保留・対立・未測定を含める** | 統合は必ず何かを落とす。**落としたものを併記しなければ、成果物は検証不能になる** |

### 2.1 特に「生成」と「承認」の境界について

AIの自律性を制限する理由を**「AIが信頼できないから」とだけ述べてはならない。** 能力向上によって失効する説明だからである。

長期的に守るべきなのは、**誰が何を生成し、誰が何を理解・承認し、どの状態が共有済みの意味なのかを混同しないこと**である。

人間が自分で表札を書く行為には、人間自身が意味へ到達する価値がある。したがってKJ法キャンバスを人間の認知訓練・探索として使う局面では、その操作をAIへ安易に置き換えない。一方、AIへ一定区間を委任し、人間が後から理解・異議・承認する局面では、AIが表札・仮説・構造を生成すること自体を禁止しない。

現在の `proposal-only` は、AI内部の思考段階を一手ずつ止める規則ではなく、**共有・承認済みの正規状態へ権限なく昇格させないための境界**として扱う。

## 3. 進化の判断基準

提案された変更が、適応なのか、価値創出なのか、逸脱なのかを判定する。

### 3.1 判定手順

1. その変更は、**意味形成の材料・途中状態・反証・来歴を、後から辿り直せる形で増やすか、失わせるか。**
2. 失わせるなら**逸脱**である。効率・UX・速度・AI自律性を理由にしても変わらない。
3. 保持したまま人間またはAIが担えるsensemakingの範囲を広げるなら、既存能力の維持は**適応**、未構築の能力は**価値創出**である。
4. KJ法以外のAI-nativeな認知手法であっても、SUIの不変条件と権限境界を満たす限り、手法が異なることだけを理由に逸脱とはしない。

### 3.2 適応の判断規則

- **AIの統合能力の向上は、入力の質の向上として受け入れる。検査を省略する理由として受け入れない。** AIが出した島立てを戻し検査と空白の列挙にかけられるなら、AIの高速性は敵ではなく入力である。
- **説明責任への適合を主張するなら、その証跡が既定で残り、照会できること。** 設計上の適合と運用上の適合を混同しない。
- **違和感を求める機会を減らす変更は、UXの改善に見えても製品の前提を掘り崩す。** 「摩擦の削減」を理由に検査を省略しない。
- **対象実務を職種名で定義しない。手続きの形で定義する。** 「未分化な状況から意味を立ち上げる」実務は職種名と独立に存在する。

### 3.3 AI経路はフレーム適用の中核である

**フレームをAIに適用する経路は、周辺機能ではなく中核である。**

したがって、AIが**未分化な素材・保留・違和感に触れられない状態は、機能不足ではなくフレームの不成立**である。フレームが扱う対象そのものをAIから隠しながら、AIに認知拡張を提供しているとは言えない。

**ただし安全境界を緩めることではない。** 解決は**信頼境界の内外でAIを区別する**ことにある——境界の内側にいるAI（ローカル/自己ホスト）にはフレームを適用でき、外側のAI（外部API）には適用できない。両者を同列に扱ってはならない。

### 3.4 逸脱の兆候

次はいずれも逸脱である。効率や利便を理由にしても変わらない。

- 検査（表札の戻し検査、空白の列挙、A/B照合）を省略できるようにする
- 保留状態を「未完了」として解消を促す
- 違和感の入力に根拠を必須化する
- 内容に点数・順位・等級を与える（画面表示を含む）
- AI生成物を、権限確認なしに `human_reviewed`・Accepted・Consensus等の人間承認済み状態へ昇格する
- 共有物から保留・対立・未測定を落とす

## 4. 価値の源泉——他が持たないもの

次は本製品の構造が既に許しており、かつ他のシステムがほぼ持たない性質である。**これらを削る変更は、代替可能性を上げる方向である。**

### 4.1 説明責任を伴わない反対の受理

現代のシステムはほぼ例外なく反対に根拠を要求する。投票には理由欄があり、レビューにはコメントが要る。**根拠を示せない反対は、システム上「入力できない」。**

本製品はこれを覆している。結果として保持できるもの:

- **言語化前の知。** 熟練者の「何か引っかかる」は、しばしば言語化される前に消える。
- **感受の分布。** 根拠要求は弁の立つ者を優遇する。要求しないことは、発言力ではなく感受を記録する。
- **後からの回収。** 違和感は当初説明できなくても、後に説明がつくことがある。保存されていなければ回収できない。

### 4.2 保留の来歴

一般の来歴は「誰が何を書いたか」を記録する。本製品の構造は「**誰が、いつ、何を、決めないままにしたか**」を記録できる。

事後の検証では、「なぜその判断に至ったか」より「**なぜその時点で決めなかったか**」の方がしばしば重要である。判断の空白期間は、現在ほとんどどこにも記録されていない。

### 4.3 不一致を操作の対象にすること

熟議支援技術の多くは合意形成を目的関数とし、非合意をプロセスの失敗として扱う。不一致を可視化する系もあるが、**可視化と、構造として保持して後から作業できることは別である。**

本製品は対立を型付き関係として持ち、矛盾を保留対象として扱う。**不一致が可視化の対象ではなく操作の対象である**ことが差である。

これは規模の話ではない。3人の熟議でも合意最適化は起こりうる。**目的関数の差**である。

## 5. 反証条件

本書の主張は反証可能でなければならない。次が観測されたとき、本書は見直しを要する。

| # | 観測 | 崩れるもの |
|---|---|---|
| F1 | 検査を実装しても成果の質に**差が出ない** | フレームの中核 |
| F2 | 説明責任を伴わない反対を受理しても、**ノイズしか集まらない** | §4.1 |
| F3 | **AIにフレームを適用しても、AI単独の統合と結果が変わらない** | §1 の存在理由そのもの |
| F4 | 「決めないままにする」ことが利用者にとって**苦痛でしかない** | 保留 |
| F5 | AIへ広いsensemaking区間を委任しても、来歴付きの理解・レビュー面が人間に実質的価値を与えない | §2.1 と人間向けcollaboration surfaceの位置づけ |

**F3 が最重要である。** §1 の定義は「フレームを適用したAIは、適用しないAIより良い結果を出す」を含意する。**これは測定可能であり、まだ測っていない。** 測定を怠ったまま §1 を主張し続けることは、本プロジェクトが自ら戒めている「測定なき改善の主張」にあたる。

F1〜F3 は自プロダクトのドッグフーディングで観測しうる。ただし**題材が自己言及的（設計判断・issue）である限り未分化な違和感が起動せず、観測できない。** 外部題材の投入が反証可能性の前提である。

## 6. 本書の適用

- 新規ADR・新規画面・新規API・データ境界の変更を起票するとき、§3.1 の判定手順を適用する。
- 「AIには〜ができないから」という論拠が現れたら、§1.2 により差し戻し、sensemakingの外在化・蓄積・権限境界に基づく論拠へ書き換える。
- §4 の性質を削る提案には、**何によって代替可能性が上がらないと言えるか**の説明を要求する。
- §5 の反証条件が観測されたら、本書を改訂する。**改訂せずに主張を維持してはならない。**
