# 島・情報集合の代表視覚手掛かり要件

- Status: Normative

## 0. 位置づけ

本書は、島または利用者が明示的に選んだ情報集合を見つけ直しやすくする、小さな絵文字・アイコン・画像の要件を定める。要件IDは `DOMAIN-VISUAL-CUE-01` とする。

ここでいう **代表視覚手掛かり（Representative Visual Cue）** は、内容を確定する分類ラベルや装飾ではない。利用者がキャンバスを見渡したときに、目的のまとまりを再認識するための補助である。島の表札、要約、カード本文、出典、根拠を置き換えない。

## 1. 解決する課題

カードや島が増えると、利用者は表札を一つずつ読み、目的のまとまりを探し直す必要がある。内容と関連する小さな視覚手掛かりを文字と併用できれば、位置と内容を結び付けて覚え、再発見しやすくなる可能性がある。

一方、内容と無関係な装飾、多様すぎる絵柄、断定的な一枚絵は、注意を奪い、曖昧さや対立を隠すおそれがある。本機能は「画像を増やすこと」ではなく、探す負担を実際に減らすことを目的とする。

## 2. 対象と非目標

### 2.1 対象

- `Island`。島の表札と併記する。
- 利用者が明示的に選んだ複数カードまたは島の集合。選択範囲を確認してから候補を探す。
- 一つの対象につき、採用中の手掛かりは原則一つとする。候補は採用前の一時状態として扱う。

カード一枚ごとの常設画像、文書全体への自動付与、島作成時の自動生成は既定動作にしない。

### 2.2 非目標

- 見栄え、賑やかさ、利用時間、クリック数を増やすこと。
- 画像による自動分類、品質評価、重要度評価、感情判定。
- 表札、要約、本文、根拠、出典、レビュー状態の代替。
- 画像を事実、証拠、合意済み解釈として扱うこと。
- 利用者の確認なしに画像を生成、取得、採用、共有すること。

### 2.3 標準KJ法・派生実践との連続性

標準的なKJ法の図解化は、完成した挿絵を作る作業ではない。表札・ラベルの束にシンボルマークを付けて空間配置し、島どり線や関係線などの記号で全体の構造を表す。簡単な手描きの印でも、まとまりを一目で識別して並べ替える役割を果たす。

派生実践では、文章の代わりに写真や図解をラベルとして扱う方法、フィールドワーク中の写真・動画を記憶や原記録へ戻る手掛かりにする方法、紙とペンの操作をデジタルペンやカード操作ソフトで記録・共有する方法が見られる。表計算・プレゼンテーションソフトの矩形、囲み、線、矢印を使う実践も、紙上のラベルと図解記号を汎用図形で再現したものと位置づけられる。

sui-sensemakingはこの連続性を保ち、次を優先する。

- 絵が得意でなくても使える、自由線、基本図形、単色、短い文字を組み合わせた小さな手描き手掛かり。
- 利用者自身が撮影・作成・取り込んだ写真や図から、明示的に切り出すサムネイル。
- Unicode絵文字と、由来・ライセンスを固定したプリセット。
- その後に、外部素材検索や画像生成などの現代的な候補支援。

ただし、**識別用の代表視覚手掛かり**、**カードや島の関係を表す図解記号**、**観察・取材で得た一次視覚資料**は別の概念である。写真自体が観察データや根拠である場合、縮小表示を代表手掛かりとして併用しても、元写真、撮影文脈、出典への参照を失ってはならない。

## 3. 手掛かりの供給経路

供給経路は混同せず、次の順に小さく導入する。後の経路が利用できなくても、前の経路と中核のKJ法操作は動作しなければならない。

| 経路 | 例 | 通信 | 主な利点 | 主な注意 |
|---|---|---:|---|---|
| A: 利用者作成・取込 | 手描き、基本図形、短い文字、自分で撮影・作成した写真や図 | 不要 | 従来のKJ法に近い、意図を直接表せる | 写真の機微情報、第三者の権利、原資料との混同 |
| B: 文字・同梱素材 | Unicode絵文字、製品に同梱したプリセットアイコン・画像 | 不要 | 速い、安定、外部へ内容を共有しない | OS間の絵柄差、語義の誤解、同梱素材のライセンス |
| C: 外部素材検索 | ライセンス条件を確認できるフリー素材集 | 必要 | 写真や具体物を選べる | 検索語の共有、権利表示、素材削除、ライセンス情報の誤り |
| D: 生成画像 | 設定済みの画像生成プロバイダ | プロバイダによる | 対象に合わせた候補を作れる | 入力共有、幻視的な細部、費用、待ち時間、権利・利用条件 |

- A/Bを最初の実装候補とする。手描きは高機能な描画ソフトにせず、識別に十分な自由線、基本図形、色、消去、取り消し、画像の切り抜きに限定する。絵文字を単なるUnicode文字として保存するか、特定の画像セットを同梱するかは分けて判断する。画像セットには固有の表示義務や継承条件があり得る。
- Cは検索結果のライセンス表示を信用するだけで採用してはならない。原典URLと原典側の条件を利用者が確認できるようにする。
- Dは `SUI_LLM_PROVIDER=none` を含むAI無効構成で存在しないものとして扱い、暗黙に外部プロバイダへ切り替えない。
- AからDのどの経路でも、採用後の表示上は同じ「代表視覚手掛かり」として扱う。ただし、出所と利用条件を失わない。Aの写真・図が一次資料でもある場合は、代表表示とは別に原資料参照を保持する。

## 4. 機能要件

### 4.1 低負担な選択

1. 利用者は島の詳細または選択集合の操作から「視覚手掛かりを選ぶ」を明示的に開始できる。
2. 最初に、簡単な手描き、基本図形、利用者の画像からの切り抜き、外部通信のない絵文字または同梱プリセットを選べる。
3. 外部素材検索と生成画像は高度機能として分け、利用可能な場合だけ表示する。
4. 候補は対象の表札、短い説明、含まれるカード範囲と並べて確認できる。候補だけを見て採用させない。
5. 利用者は候補を採用、見送り、別候補の表示、削除できる。未設定のまま完了できる。
6. 採用、変更、削除は取り消し可能とし、カード、島、関係の意味状態を変更しない。
7. 手描き入力はマウス、ペン、タッチ、キーボードで到達可能な代替操作を持つ。精密な描画能力を要求しない。

### 4.2 内容との対応

- 候補は、利用者が確認した島の表札・要約、または明示的に選んだカード集合から導く。
- 未レビュー本文、生の取材記録、保留中の情報は、利用者が対象と送信範囲を確認しない限り外部検索語や生成入力へ含めない。
- 曖昧さ、対立、複数の見方が中心である場合、一つの具体的解釈へ収束させない。中立的・抽象的な手掛かり、複数候補、または「設定しない」を提示できる。
- 人物の属性、感情、因果関係、場所、組織、ブランドなど、元情報にない細部を補ってはならない。
- 関連性を説明できない候補は表示しない。説明は「この画像が正しい理由」ではなく、「どの語または対象範囲を手掛かりにしたか」を短く示す。
- 取り込んだ写真・図が一次資料の場合、代表表示の切り抜きと原資料を別参照にする。切り抜きや縮小によって失われた周辺文脈を、元資料にないものとして扱ってはならない。
- 島どり線、関係線、矢印、境界などの図解記号を、代表視覚手掛かりの装飾へ変換しない。これらは関係構造として編集・読み上げできる状態を保つ。

### 4.3 アクセシビリティと表示

- 手掛かりには、利用者が確認・編集できる短い代替テキストを持たせる。絵文字にも読み上げ用の名称を設定する。
- 色、形、画像だけで島や状態を区別しない。表札と状態表示を常に利用可能にする。
- 非表示設定を用意し、画像なしでも全操作と内容理解を完了できる。
- 採用済み手掛かりは、表札付近、折りたたみ表示、一覧・ミニマップなど再認識しやすい場所へ小さく表示する。カード本文を覆わない。
- 固定寸法または固定アスペクト比、遅延読み込み、代替表示を使い、読み込み前後でキャンバスをずらさない。アニメーションを既定で使用しない。

### 4.4 外部通信とSafeMode

- 外部素材検索または生成を開始する前に、接続先、共有する検索語・説明・対象範囲、共有しない情報を確認できる。
- 明示的な実行操作までは通信しない。候補パネルを開くだけで検索・生成してはならない。
- SafeModeがONのときはレビュー済みの許可情報だけを外部入力へ投影し、条件を満たせない場合は外部経路を停止する。
- 外部経路の失敗を、別の素材サービスや生成プロバイダへの暗黙の切替で補わない。
- 外部由来のタイトル、説明、タグ、埋め込みメタデータは表示データとして扱い、命令として実行しない。

### 4.5 権利・出所

外部素材または画像セットを採用する場合、少なくとも次を保持し、共有前に確認できるようにする。

- 素材ID、原典URL、作者または提供者、取得元サービス、取得日時。
- ライセンス識別子とライセンスURL、表示義務、改変の有無。
- 素材の取得時点で確認した条件。後日原典が消えても、採用判断の根拠を辿れること。
- 共有・export時に必要なクレジット表記。表記できない形式には当該素材を含めないこと。

初期の許容ライセンス範囲は、商用利用、改変、再配布、表示義務、継承条件を製品の配布形態と照合して別途決定する。`CC0`、`CC BY`、`CC BY-SA` は同じ条件ではない。検索サービスが示す情報は補助であり、利用可能性の保証として扱わない。

### 4.6 保存・共有・削除

- 実装前に、採用済み手掛かり、候補、サムネイル、権利情報の保存先と容量上限を決める。現行 `DocumentV1` に未決定フィールドを追加しない。
- 公開、レビューパック、exportには既定で含めない。利用者が含める場合は、画像、代替テキスト、必要な権利表示、生成物である旨を同じ確認画面で示す。
- 共有物で画像だけが残り、対応する表札・説明・対象範囲が失われる状態を作らない。
- 削除時は採用参照と派生サムネイルを削除する。元カード、島、表札、要約は変更しない。
- 生成画像では、プロバイダ、モデルの安全な識別子、生成日時、入力投影のdigest、対象参照、人間による採用状態を記録する。秘密情報や生の認証情報は保存しない。

## 5. 段階導入

### Phase 0: 要件・評価fixture

- 紙のシンボルマーク、簡単な手描き、基本図形、撮影写真、画像なし、絵文字、同梱プリセット、外部素材、生成画像を同じ代表タスクで比較する。
- 具体的な内容、抽象的な内容、対立を含む内容、機微情報を含む内容のfixtureを用意する。
- 写真が単なる識別手掛かりの場合と、観察データ・根拠である場合を分ける。
- 既定画面への常設UI追加は行わない。

代表場面、比較条件、測定項目、停止条件は `02_Architecture/representative_visual_cue_evaluation.md`、機械可読fixtureは `02_Architecture/design/representative_visual_cue/phase0_scenarios.json` を正本とする。

### Phase 1: 従来実践と連続するオフライン選択

- 自由線、基本図形、単色、短い文字、利用者画像の切り抜き、Unicode絵文字またはライセンスを固定した小規模プリセットを、明示操作で選択・解除できるようにする。
- 代替テキスト、キーボード操作、非表示、取り消し、固定寸法を検証する。

### Phase 2: 権利確認済み外部素材

- 許可するプロバイダとライセンスを許可リストにし、原典確認、出所保存、クレジット生成、SafeMode送信前確認を実装する。
- API利用条件、キャッシュ可否、削除要請、サービス停止時の表示を確認する。

### Phase 3: proposal-only画像生成

- 生成入力のプレビュー、明示送信、複数候補、採用前無変更、生成来歴を実装する。
- AI無効構成とローカル素材経路を維持する。

## 6. 受入条件

- [ ] AC-1: 画像なしでも、島の作成、編集、探索、共有を完了できる。
- [ ] AC-2: 利用者が対象範囲を確認し、手描き、基本図形、画像切り抜き、絵文字またはプリセットをマウスとキーボードで選択、変更、削除、取り消しできる。
- [ ] AC-3: 手掛かりは表札・説明と併記され、画像だけで意味・状態・根拠を伝えない。
- [ ] AC-4: 代替テキストを確認・編集でき、手掛かりの非表示時も同等の内容へ到達できる。
- [ ] AC-5: 候補パネルを開くだけでは外部通信せず、外部検索・生成前に接続先と共有内容を確認できる。
- [ ] AC-6: SafeModeで許可されない本文・属性が検索語や生成入力へ含まれず、暗黙のプロバイダ切替がない。
- [ ] AC-7: 外部素材の原典、作者、ライセンス、取得時点、改変、必要なクレジットを保存・表示・exportできる。
- [ ] AC-8: 生成画像はproposal-onlyであり、採用前に正本を変更せず、生成来歴と人間の採用状態を辿れる。
- [ ] AC-9: 代表規模で読み込みによるレイアウト移動や対話操作の停止がなく、390px幅でも操作と文字が見切れない。
- [ ] AC-10: 画像なし、絵文字、画像併用を比較し、目的の島を見つける時間、見誤り、再認識、主観的負担が悪化しない。見栄えや利用時間だけを成功指標にしない。
- [ ] AC-11: 曖昧・対立・機微情報fixtureで、一面的な具体化、根拠のない細部、意図しない外部共有が発生しない。
- [ ] AC-12: 写真・図が一次資料である場合、代表表示を削除・変更しても元資料、撮影文脈、出典が維持され、元資料へ戻れる。
- [ ] AC-13: 島どり線・関係線などの図解記号と代表視覚手掛かりが別の操作・意味・アクセシビリティ情報として保たれる。

## 7. KJ法実践と評価の根拠

### 7.1 標準KJ法・派生技術

- 川喜田研究所は、現場取材データをラベルへ記入し、グループ編成、図解化、叙述化へ進む一連の方法としてKJ法を説明している: https://kj-kawakita.co.jp/about_kj-method/
- 実践手順では、表札・ラベルの束にシンボルマークを付け、空間配置後に島どり線や関係線を描く。また、文章ラベルの代わりに写真や図解を用いる実践も示されている: https://www.everfield.co.jp/KJ/step.html 、https://tanokura.net/information/kj-method-18/
- 写真KJ法のワークショップ実践が報告されており、写真をカードとして扱う派生技術が存在する: https://www.jstage.jst.go.jp/article/jje/56/Supplement/56_1A2-01/_pdf
- フィールドワークの写真・動画は、後の議論で記憶を辿る資料として有用だったと報告されている: https://www.jstage.jst.go.jp/article/iappmjour/14/1/14_358/_pdf
- デジタルペンによるグループKJ法支援は、紙とペンの利点を残しながら、ラベルの内容・位置・向き・作業過程を記録して共有する方針を採っている: https://www.jstage.jst.go.jp/article/transinf/E94.D/3/E94.D_3_456/_article
- KJエディタは、カード関係だけでなく欠けている情報の発見と、創造的思考過程の記録・後からの解釈を支援するものとして評価されている: https://www.sciencedirect.com/science/article/pii/S0950705197000154

これらから、現代化の中心は華美な画像生成ではなく、従来の素早い印、写真ラベル、空間配置、関係記号を低摩擦で保存・再利用し、必要な場合だけ検索・生成支援を加えることとする。

### 7.2 認知負荷

- 関連する説明画像は記憶を助け得る一方、装飾画像は同じ効果を示さない研究がある: https://www.sciencedirect.com/science/article/pii/S0747563212000921
- 装飾画像の多様さが処理負担を増やし、学習成果を改善しなかった実験がある: https://www.sciencedirect.com/science/article/pii/S0001691822003134
- 表象的な画像は課題成績と主観的な容易さを改善したが、装飾画像では同等の効果が確認されなかった: https://www.sciencedirect.com/science/article/pii/S0959475219307054
- 画像の再認記憶が単語を上回る条件はあるが、手掛かりの効果は課題とモダリティに依存する: https://pubmed.ncbi.nlm.nih.gov/21287031/ 、https://pubmed.ncbi.nlm.nih.gov/24203897/
- Creative Commons自身も、検索結果の権利情報を独立に確認するよう求めている: https://creativecommons.org/terms/

したがって、画像を一律に増やせば認知負荷が下がるとは仮定しない。文字との併用、内容との関連性、人間による採用、非表示可能性、代表タスクでの比較検証を要件とする。
